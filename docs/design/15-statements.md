# 15. 明細（S5 の画面仕様）

[05 画面と体験](05-ui-ux.md) §2.2 の詳細。S5（Issue #6）で作る「明細」の画面（未処理の明細を 1 行の中で 登録・振替・無視 する）、推定、自動登録ルール（設定 › ルール）、口座間振替の照合、それらを支える台帳の操作を定めます。明細の取込（S4: CSV・Stripe）、証憑のアップロードと紐づけの本体（S6）、ホームの「やること」の表示（S7）は範囲外で、結び目だけをここに書きます。

## 1. 明細の状態と台帳の操作

明細（`WalletTransaction`）は取り込んだら削除せず、`status` で片付ける。登録・振替は S3 の台帳の操作（`postJournalEntryInTransaction` / `voidJournalEntryWithOpenDate`）の上に置き、仕訳は書き換えない。

| 状態 | 意味 | 仕訳 |
| --- | --- | --- |
| `pending` 未処理 | 取り込んだまま | なし |
| `registered` 登録済み | 収入・支出として登録した | 1 件（`kind = normal`） |
| `transfer` 振替 | 口座間の移動として登録した | 1 件（`kind = transfer`）。相手の明細があれば 2 明細が同じ仕訳を指す |
| `ignored` 無視 | 帳簿に載せない（私用・重複・残高調整など） | なし |

- **登録** `registerWalletTransaction(id, input)`: 未処理 → 登録済み。仕訳は `sourceKind = wallet_txn`・`sourceId = 明細の ID`・日付 = 明細の日付（`txnDate`）。出金（`amount < 0`）は 借方 科目の行（分割なら複数）／税抜経理なら 借方 仮払消費税／貸方 口座（科目と補助科目）|金額|。入金（`amount > 0`）は 借方 口座／貸方 科目の行（複数可）／税抜経理なら 貸方 仮受消費税。科目の行の金額は税込で受け、`splitTaxInclusive`（11 §1 と同じ分割・経過措置を含む）で税額を持つ。摘要は入力（既定は明細の摘要そのまま。200 字で切る）、取引先は科目の行に、口座の行は税区分 `na`・セグメントは口座の既定。科目は 口座に紐づく科目・現預金・仮受仮払 を選べない（`isReservedAccount`。口座どうしの移動は振替）。入金は 収益・資産・負債・純資産（資本金の払込や借入の入金）、出金は 費用・資産・負債（前払・固定資産・未払金や借入金の返済）の科目。収益・費用の行はセグメント必須（台帳の `SEGMENT_REQUIRED`）。
- **振替** `transferWalletTransaction(id, input)`: 未処理 → 振替。相手の指定は 3 通り（§8）。(a) 相手口座の未処理の明細（同額・逆符号）: 1 仕訳（借方 入金側の口座／貸方 出金側の口座、金額 |金額|）を作り、両方の明細を `transfer` にして同じ仕訳を指す。(b) 相手口座だけ（明細はまだない）: 同じ形の仕訳を作り、この明細だけを結ぶ。手数料があれば 11 §4.3 の振替と同じ行（支払手数料 5400・出金側から引く）。(c) 登録済みの振替の仕訳: 新しい仕訳を作らず、この明細をその仕訳に結ぶだけ。
- **無視** `ignoreWalletTransaction(id, { reason? })`: 未処理 → 無視。理由は任意（`ignoredReason`）。
- **未処理に戻す** `reopenWalletTransaction(id, { reason? })`: 無視 → 未処理（理由は任意）。登録済み・振替 → 仕訳を `voidJournalEntryWithOpenDate` で取り消し（反対仕訳。理由は必須。締め済みなら開いている最初の日付）、その仕訳を指す明細をすべて未処理に戻す（`journalEntryId = null`）。仕訳が取引の画面で既に取消済み・訂正済みなら取消は飛ばして明細だけ戻す（訂正後の仕訳は残る。要るなら取引の画面で取り消す）。
- **5 秒の取消**（§7）は `reopenWalletTransaction` を理由「登録直後の取消」で呼ぶ。内部は反対仕訳で、連番は消費する（帳簿の不変性）。
- **メモ** `updateWalletTransactionNote(id, { note })`: どの状態でも。仕訳には書かない。
- 仕訳の日付は明細の日付で固定する（会計上の日付を変えない）。日付が締め済み（`lockedThrough` 以前）なら登録・振替は台帳が `PERIOD_LOCKED` で拒否し、行に「2026/12/31 までは締めています。登録するには 設定 › 会計期間 で締めを戻してください」と出す。日付がどの会計期間にも入らないときも同様（`OUT_OF_FISCAL_YEAR`）。
- 金額 0 の明細は無視だけできる。無効な口座の明細は一覧に出るが登録・振替はできない（「口座が無効です。設定 › 口座 で有効にしてください」）。
- 同じ明細への同時の操作は明細の行ロック（`FOR UPDATE`）で直列にし、2 回目は「この明細は処理済みです。画面を読み込み直してください」（`STATEMENT_NOT_PENDING`）で拒否する。
- 監査ログ: `wallet_transaction.register` / `.transfer` / `.ignore` / `.reopen` / `.update`（メモ）。`before` / `after` は `{ status, journalEntryId, ignoredReason, ruleId, autoPosted, note }`、理由つき。自動登録（§11）は actor を取込の実行者にし、`after.autoPosted = true`。ルールは `rule.create` / `.update` / `.activate` / `.deactivate` / `.apply`（既存の未処理への適用。`after` に件数）。監査ログの対象の表示名は「明細 2026/12/01 −88,000」「ルール 家賃」。

## 3. 一覧 `/statements`

- PageHeader: 題名「明細」、meta に「未処理 n 件」。
- URL の検索パラメータが正（再読み込みや共有で同じ結果）: `wallet`（口座 ID。なければ全部）、`status`（`pending` 既定 / `registered` / `transfer` / `ignored`）、`q`（検索）、`by`（`rule` = ルールで自動登録したもの。処理済みのタブだけ）、`page`。想定外の値は既定に落とす（11 §3 と同じ `lenient`）。
- 口座チップ: 「すべて n」と口座ごと（名前と未処理の件数。0 件でも出す。無効な口座は未処理があるときだけ）。リンクで `wallet` を切り替え、`status` と `q` は保つ。
- 状態タブ: 未処理（件数つき）/ 登録済み / 振替 / 無視。右に検索（GET フォーム。摘要・振込人の部分一致。数字と区切りだけなら金額の完全一致 |金額|）。処理済みのタブでは「ルールで自動登録」のチェック（`by=rule`）。検索欄は `/` でフォーカスする。
- 表（PC の列）: 選択 ・ 日付 ・ 摘要（取込のまま。長いときは折返し。下に口座名、振込人があれば「振込人: …」を小さく）・ 金額（右揃え。入金はそのまま「12,340」、出金は「−12,340」。色は変えない）・ 推定（§4 のチップ）・ 操作。行の高さは最低 40px で、摘要の折返しとチップで伸びる。
- 未処理の行の推定: 科目 ・ 税区分 ・ 取引先 ・ セグメント のチップ。ルール一致は実線、それ以外の推定は点線、空は「科目を選ぶ」のような点線の薄いチップ。振替の推定は「振替 → 架空銀行 12/26 +10,604」の実線（ルール）または点線（候補）のチップ 1 つ。出金で証憑の紐づけ（`DocumentLink.walletTransactionId`）がない行には warn 色の小さな「証憑なし」チップ（S6 までは常に出る）。
- 未処理の行の操作: 主操作のボタン（primary・sm。既定「登録」、推定が振替なら「振替」、ルールの動作が無視なら「無視」）、「無視」（ghost・sm。主操作が無視のときは「登録」）、「…」（§5）。
- 処理済みの行: 推定の代わりに結果。登録済み → 「No. 12 · 地代家賃」（仕訳の詳細 `/entries/[id]` へのリンク。科目は口座以外の最初の行、2 行以上なら「ほか n 行」）。振替 → 「No. 14 · 振替 → 架空銀行」。無視 → 「無視」と理由。自動登録なら「ルールで自動登録」を muted で添える。仕訳が取消済み・訂正済みならその旨（「取消済み」「→ No. 20 に訂正」）。操作は「…」だけ（取引を開く / 未処理に戻す / メモ）。
- スマホ（768px 未満）: 2 段。1 段目 日付・摘要（口座）／金額、2 段目 チップ（横にはみ出すときは横スクロール）と 主操作・無視・「…」。選択のチェックは 1 段目の左。
- 並び: 未処理は日付の昇順（古いものから片付ける）、同じ日付は取込順（ID の昇順）。処理済みは日付の降順。50 件ごとに「前へ / 次へ」と「n 件」。
- 空のとき: 未処理が 0 件なら「未処理の明細はありません」（説明「取り込んだ明細はここに並びます。取込は明細の取込（準備中）から」。S4 の merge 後は取込への導線に替える）。絞り込み（口座・検索・`by`）で 0 件なら「条件に合う明細がありません」と「絞り込みを外す」。

## 4. 推定

`packages/ledger/src/suggest.ts` の純粋関数 `suggest(line, context)`。明細 1 行と、ルール・履歴・取引先・科目・口座・振替の候補を受け、チップの初期値と主操作を返す。順序は固定で、先に決まったものを後の段が上書きしない。

1. **ルール一致**: 有効なルールを `priority` の降順（同じなら作成順）に試し、最初に一致したもの（§10 の条件）。動作が 登録 / 候補 なら科目・税区分・取引先・セグメント・摘要の雛形、振替なら相手口座（相手口座に候補の明細があればそれも）、無視なら無視。チップは実線。`autoPost` が true で動作が 登録 / 振替 / 無視 なら取込時に自動で片付ける（§11）。
2. **振替の候補**（ルールが一致しないとき）: §8 の候補が 1 つ以上あれば振替を推定し、日付が最も近い候補を選ぶ。チップは点線の「振替 → …」。
3. **過去の同じ摘要の登録**: 摘要のキー（下記）が同じ、処理済み（登録済み・振替）の明細のうち最新のもの。同じ口座を優先し、なければ他の口座。登録済みなら その仕訳の科目の行（口座以外の最初の行）の 科目・税区分・取引先・セグメント を、振替なら相手口座を写す。点線。
4. **取引先の既定**: 取引先の名前かカナ（正規化後）が摘要か振込人に含まれる取引先（複数なら名前が長いもの）。`partnerId` と、取引先の既定の 科目・税区分・セグメント で空いている項目を埋める。点線。
5. **科目の既定**: 科目が決まっていれば、空いている税区分を科目の既定の税区分（方向が合うものだけ: 入金は 売上側か対象外、出金は 仕入側か対象外）、空いているセグメントを 科目の既定 → 口座の既定 の順で埋める。科目が決まらなければ、セグメントだけ口座の既定で埋め、科目と税区分は空のまま（Enter で編集が開く）。点線。

- 摘要のキー `descriptionKey(text)`: NFKC 正規化 → 小文字 → 空白・数字・記号を除く。「Vデビット GOOGLE CLOUD JAPAN 11/05」と「Vデビット GOOGLE CLOUD JAPAN 12/05」は同じキー。ルールの「摘要に含む」「振込人に含む」も同じ正規化で比べる（大文字小文字・全角半角・空白の違いを無視）。
- 結果 `Suggestion`: `mode`（`register` / `transfer` / `ignore`）、`source`（`rule` / `candidate` / `history` / `partner` / `default` / `none`）、`ruleId`、`autoPost`、`accountId`・`taxCategoryCode`・`partnerId`・`segmentId`・`description`（それぞれ `null` あり）、`transferToWalletId`、`candidate`（候補の種類と ID）、`sources`（項目ごとに `rule` / `history` / `partner` / `default` / `null`。チップの実線・点線に使う）。
- 推定は一覧を開くたびに計算する（ルールや履歴の変化を反映する）。取込時には §11 がスナップショットを `WalletTransaction.suggestion` に保存する（自動登録の根拠として残す）。画面で編集した推定はブラウザの中だけに持ち、登録で確定する。次回から変えたいときは「ルールにする」。
- 正規表現は `descriptionRegex` を NFKC 正規化した摘要に `iu` フラグで当てる。保存時に `new RegExp` で検証し、200 字まで。実行時の例外は不一致として扱う。

## 5. 行の操作

- **登録**（主操作のボタン・Enter）: 行のチップの値で登録する。科目がなければ登録せず編集ポップオーバーを科目にフォーカスして開く。サーバーの拒否（セグメント必須・締め済み・税率の規則なし …）は行のチップの下に赤字で出し、行は未処理のまま。成功で行は薄くなり、5 秒の取消（§7）を出してから一覧から消える。焦点は次の行へ。
- **無視**（I）: 理由なしで即座に無視。理由をつけるときは「…」の「理由をつけて無視」。
- **振替**（T・推定が振替のときの主操作）: §8 のポップオーバー。推定が振替で候補が決まっているとき、主操作（Enter）はポップオーバーを開かずに最も近い候補で振替する。
- **編集**（E・チップのクリック）: ポップオーバーに 科目（select。出金は 費用 → 現預金以外の資産 → 負債、入金は 収益 → 資産 → 負債 → 純資産 の順。口座の科目・現預金・仮受仮払は出さない）、税区分（方向のグループを先に）、取引先、セグメント、摘要（既定は明細の摘要）。科目を変えたら未編集の税区分・セグメントを科目の既定で埋める（11 §4 と同じ規則）。「登録」（primary。Enter）と「キャンセル」（Esc）。下に「分割」「ルールにする」へのリンク。
- **ルールにする**（R）: §10 の Sheet を、口座 = この明細の口座、「摘要に含む」= 摘要のキーに近い文字列（数字を除いた摘要。編集できる）、符号 = この明細の符号、動作 = 行のチップの値（振替の推定なら振替）で開く。「次回から: 候補として表示 / 自動で登録」の選択（既定は候補）と、自動のときは「一致する未処理 n 件も今すぐ登録する」のチェック。保存すると行のチップは実線になり、今すぐ登録を選んだ行は片付く。
- **「…」**: 証憑を紐づける（S6 まで「準備中」の非活性）、メモ（dialog の textarea。`note` に保存。メモがある行は摘要の下に小さく出す）、分割（§9）、理由をつけて無視（dialog。理由の text）。処理済みの行では 取引を開く（リンク）、未処理に戻す（登録済み・振替は理由必須の ConfirmDialog。反対仕訳の日付を文で出す。無視は確認だけ）、メモ。
- **複数選択**: 行の左のチェック（Space）。1 件以上で表の上に帯「選択 n 件 · 登録 · 無視 · 解除」。一括登録は ConfirmDialog に「n 件を登録します。入金 x 円 / 出金 y 円」。科目のない行は登録せず「科目のない m 件は登録しませんでした」と残す。一括無視は件数を確認。処理は 1 件ずつ順に行い（同時実行で採番を争わない）、失敗した行はその理由を行に残す。

- 未処理のタブを開いたとき、最初の行に焦点を当てる（検索は `/`）。行が片付いたら焦点は次の行（末尾なら前の行）。ポップオーバーの中は Tab で巡り、Enter で送る（textarea を除く）。焦点の見た目は消さない（`:focus-visible` のアウトライン）。

## 7. 5 秒の取消

- 登録・振替・無視の直後、画面の下中央に「No. 12 を登録しました」「2 件を振替にしました」「無視しました」と「取消」ボタンの帯を 5 秒出す（共通の Toast と同じ位置・見た目。ボタンがあるため明細の画面の部品として持つ）。次の操作で前の帯は閉じる（取消できるのは直前の 1 件）。
- 取消（ボタン・Z）は `reopenWalletTransaction` を理由「登録直後の取消」で呼ぶ。登録・振替は反対仕訳で取り消し、明細（振替なら 2 件）は未処理に戻って一覧の元の位置に現れる（チップは取消前の値）。無視は状態だけ戻す。
- 5 秒を過ぎたら「…」の「未処理に戻す」（理由を書く）で同じことができる。

## 8. 振替と照合

- 候補 `findTransferCandidates(txn)`: 次の 2 種類を日付の近い順に最大 5 件ずつ。
  - 相手の明細: 他の有効な口座の未処理の明細で、金額が逆符号の同額（`amount = −txn.amount`）、日付が ±5 日。
  - 登録済みの振替の仕訳: `kind = transfer`・`posted` の仕訳で、日付が ±5 日、この口座の科目と補助科目の行（入金なら借方、出金なら貸方）の金額が |金額| に等しく、この口座の明細がまだ結ばれていないもの（片側だけ先に登録した振替や、取引の画面で手入力した振替）。
- ポップオーバー: 候補の一覧（radio。先頭が選ばれている。「架空銀行 12/26 +10,604 振込 ストライプジャパン」「No. 13 12/27 カード引落（手入力）」の形）と、「相手口座を選ぶ」（候補がないときはこれだけ）: 口座の select（有効な口座。自分は除く）と 手数料（任意・円。出金側の口座から引く。11 §4.3 と同じく 支払手数料 5400）。「振替」（primary・Enter）。
- 相手口座だけの振替: 出金の明細（金額 a・手数料 f）なら 入金側が受け取る金額は a − f、入金の明細（金額 a・手数料 f）なら 出金側は a + f を払う。仕訳の行は 11 §4.3 の振替と同じ（`buildSimpleEntry` の `transfer` に `sourceKind = wallet_txn` を付ける）。
- Stripe の payout（Stripe 残高 → 普通預金）、カードの引落（普通預金 → 未払金）、現金の預入・引出（普通預金 ↔ 現金）はこの形で結ぶ。相手の明細を結ぶと 2 つの明細が同じ仕訳を指し、どちらから見ても「振替 → 相手の口座」になる。
- ルールの動作が振替（相手口座つき）のとき: 相手口座に候補の明細があればそれを結び、なければ相手口座だけで登録する。自動登録でも同じ。

## 9. 分割

- 「…」の「分割」で開く。行の表: 科目 ・ 税区分 ・ 金額（税込・円）・ セグメント ・ 摘要（任意）。最初は 2 行で、推定の科目を 1 行目に入れる。「行を追加」「×」。上に 取引先（仕訳全体）、摘要（既定は明細の摘要）。下に 合計 / 明細の金額 / 差額。差額が 0 になるまで「登録」を無効にし、差額は太字（赤にしない）。サーバーも合計の不一致を `SPLIT_MISMATCH`（「行の合計 3,500 円が明細の金額 3,980 円と合いません」）で拒否する。
- 仕訳は 1 件: 科目の行ごとに税額を分け（税抜経理なら仮払・仮受の行を 1 本にまとめる）、口座の行は |金額| の 1 本。貸借一致は台帳が検証する。
- 分割した明細も `registered` で、結果は「No. 15 · 消耗品費 ほか 1 行」。

## 10. ルール `/settings/rules`

- 表: 名前 ・ 口座（すべて / 口座名）・ 条件の要約（「摘要に「カクウフドウサン」 · 出金 · 50,000〜100,000」）・ 動作の要約（「登録: 地代家賃 / 課税仕入 10% / 架空不動産 / 鎌倉」「振替 → 現金」「無視」「候補: 通信費 / …」）・ 自動登録（○ / —）・ 優先度 ・ 適用（`hitCount` と最終日）・ 状態。並びは 優先度の降順 → 名前。無効は畳む（「無効 n 件を表示」）。「ルールを追加」で Sheet。行の「編集」で同じ Sheet。
- Sheet（追加・編集。「ルールにする」も同じ部品）:
  - 名前（任意。空なら条件の要約を表示名にする）、口座（すべて / 口座）。
  - 条件（1 つ以上必須）: 摘要に含む、摘要の正規表現、振込人に含む、金額の下限・上限（|金額|・円）、符号（どちらも / 入金 / 出金）。すべて AND。
  - 動作: 登録 / 振替 / 無視 / 候補。登録は 科目（必須）・税区分（必須。科目を選んだら既定で埋める）・取引先・セグメント・摘要の雛形（任意。空なら明細の摘要）。振替は 相手口座（必須）。無視は 理由（任意）。候補は 科目・税区分・取引先・セグメント のうち 1 つ以上。
  - 取込時に自動で登録（Switch。登録 / 振替 / 無視 だけ。候補では出さない）。優先度（整数 −100〜100。既定 0。大きいものが先）。
  - 下に「いま一致する未処理 n 件」（条件を変えるたびに数え直す。`countRuleMatches`）。自動登録のときは「保存して n 件に適用」ボタンも出す（ConfirmDialog: 件数と入金・出金の合計）。
  - 保存 / キャンセル。編集の Sheet には「無効にする / 有効にする」。削除はない。
- 既存の未処理への適用 `applyRuleToPending(ruleId)`: 未処理の明細のうち、推定（§4）でこのルールが勝つものを自動登録と同じ手順で片付ける（§11）。結果は「n 件を登録、m 件は失敗（理由）」のトースト。
- 条件・動作は `Rule.match` / `Rule.action` の JSON（01 §2）。金額は文字列の整数で持つ（JSON の数値を金額に使わない）。読むときは Zod で検証し、壊れた行は一致させない。
- 一致の判定 `matchesRule(rule, line)`: 口座（`walletId` が null なら全部）、符号、|金額| の範囲、摘要に含む（正規化）、正規表現、振込人に含む（正規化。振込人がなければ不一致）。

## 11. 取込時の自動登録

- `settleImportedWalletTransactions(db, txnIds, { actor })`: 取り込んだ直後の未処理の明細に対して、推定を計算して `suggestion` に保存し、`autoPost` のルールが勝った明細を 登録 / 振替 / 無視 で片付ける（`ruleId`・`autoPosted = true`・`settledAt`。ルールの `hitCount` と `lastHitAt` を進める）。振替は相手口座の未処理の候補があれば結び、なければ相手口座だけで登録する。失敗（締め済み・セグメントなし・税率の規則なし …）は未処理のまま残し、`suggestion.error` に理由を入れて返す（`{ registered, transferred, ignored, failed: [{ id, message }] }`）。
- 呼び出しは S4 の取込（CSV・Stripe 同期）が、明細を INSERT したトランザクションの後に行う（取込の失敗と自動登録の失敗を分ける）。S4 が main に入ったら結ぶ。S5 の PR の時点で未 merge なら、Issue #6 にその旨をコメントし、手動の「ルールを適用」（§10）で代用できる。
- 自動登録した明細は未処理に出ず、処理済みのタブで「ルールで自動登録」（`by=rule`）で絞り込める。

## 13. 受け入れ条件

Issue #6 の条件に加えて:

- 未処理の明細を Enter / I / T だけで片付けられ、seed の未処理 11 件が 15 操作以内に 0 件になる。
- 登録した仕訳は明細の日付で、`sourceKind = wallet_txn`、科目の行と口座の行が貸借一致し、税抜経理の期では仮受・仮払の行が付く（単体テストと DB のテスト）。

- 分割した明細の仕訳は貸借一致で、行の合計が明細の金額と一致する。不一致はサーバーが拒否する。
- ルールの一致は実線、推定は点線で見分けられる。「ルールにする」で作ったルールが次の一覧から効く。自動登録のルールに一致する明細は `settleImportedWalletTransactions` で未処理に出ず、処理済みから「ルールで自動登録」で引ける。
- 390px で行が 2 段になり、登録・無視・振替ができ、横スクロールが出ない（チップの列を除く）。
- `npm run check`、`test:db`、`next build` が通る。
