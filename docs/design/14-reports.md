# 14. 報告と書き出し（S7 の画面仕様）

[05 画面と体験](05-ui-ux.md) §2.1・§2.5 と [04 外部連携](04-integrations.md) §8 の詳細。S7（Issue #8）で作る「報告」の 6 つのタブ、ホーム、設定の「書き出しとバックアップ」、他レーンが使う PDF の基盤（`apps/web/lib/pdf/`）を定めます。資金繰り（v2 #19）、消費税の集計と決算書（v2 #15）、残高の見通し、証憑そのものの保存（S6）は範囲外です。取引先別・タグ別・科目別の集計、取引先の詳細、月次推移の前年同月は v2 #50 で §15 に足しました。

## 1. 共通の決まり

- 数字はすべて登録済みの仕訳から毎回導出する（derive, don't sync。[00 §5](00-overview.md)）。残高や集計を DB に持たない。取消済みの仕訳と反対仕訳はどちらも台帳にあり合計で 0 になるので、残高はそのまま足し、仕訳帳では状態を見せる。
- 期間は URL の検索パラメータが正（再読み込みや共有で同じ結果になる）。`fy`（第 n 期の `no`。既定は今日を含む期）、`period`（`month` 今月 / `year` 今期 / `custom` 任意。既定は `year`）、`from`・`to`（`custom` のとき。期の範囲に切り、逆なら入れ替える）、`segment`（セグメント id。空は全社）。今月は今日の属する月を期の範囲で切る（期首前なら期首の月、期末後なら期末の月）。
- 時点の数字（貸借対照表・現預金・繰越）は `to` の日付まで、期間の数字（損益計算書・月次推移・セグメント損益・仕訳帳・総勘定元帳の行）は `from`〜`to`。
- 決算振替（期末の締めで #14 が作る `kind = closing` の仕訳。収益・費用 → 繰越利益剰余金）は、対象の期の分とその取消の反対仕訳を、試算表・月次推移・セグメント損益（とホームの損益）の集計から除く。締めた期も損益は稼いだとおりに出し、貸借対照表は「3200 ＋ 前期以前の損益 ＋ 当期純利益」のまま合う（決算書と同じ、[17 §1](17-financial-statements.md)）。前の期の決算振替は含める（当期首の繰越利益剰余金になる）。仕訳帳と総勘定元帳は決算振替をそのまま出す（締めた期の損益の科目は総勘定元帳の末尾で 0 になる）。
- セグメントの切替は損益に効く（試算表の損益計算書、月次推移、仕訳帳、総勘定元帳）。貸借対照表と現預金は常に全社（貸借対照表の行はセグメントを持たないことがある）。セグメント損益のタブは比較そのものなので切替を出さない。
- 試算表の恒等式（資産 = 負債 + 純資産 + 当期純利益、借方合計 = 貸方合計、内部科目 = 0）は `@niho-finance/ledger` の `assertTrialBalanceIdentity` で毎回確かめ、合わなければ表の上に警告帯を出す（起きないはずのこと。起きたら監査ログと DB のガードを疑う）。
- 金額は整数の円。画面は 3 桁区切り・右揃え・tabular で、単位「円」は見出しに置く。マイナスは記号で表し赤で塗らない（[05 §3](05-ui-ux.md)）。
- CSV は UTF-8（BOM 付き）・CRLF・ダブルクォートで囲み、金額は符号付き整数（3 桁区切りなし）、日付は `YYYY/MM/DD`。ファイル名は ASCII（`trial-balance_20261102-20270331.csv` のように `<report>_<from>-<to>.<ext>`）。
- PDF は A4、日本語は同梱の Noto Sans JP（§12）。上に 会社名・題名・期間（第 n 期）、下に 出力日時と「n / N ページ」。数字は右揃え。仕訳帳と総勘定元帳と月次推移は横向き。
- 書き出し（CSV / PDF / freee / 弥生 / beancount / 証憑 / バックアップ）はすべて監査ログに `export.download`（entity `export`、`after` に種類・形式・期間・セグメント）で残す（[01 §8](01-domain-model.md)）。
- 文言: タブと節は名詞句（試算表 / 月次推移 / セグメント損益 / 現預金 / 仕訳帳 / 総勘定元帳）、ボタンは「CSV」「PDF」「書き出す」。内部の識別子や enum を見せない。
- スマホ（768px 未満）は閲覧だけ。縦長の表は「科目・残高」の 2 列に畳み、横に広い表（月次推移・仕訳帳・総勘定元帳）は横スクロールにする。320px で主要な列と操作が欠けない。
- 読みは Server Components、書き出しは GET の route handler（ブラウザのダウンロードになる）。route handler は会社・第 1 期・勘定科目がなければ `/setup` へ redirect する（ページの layout と同じ条件）。

## 3. 試算表 `/reports/trial-balance`

合計残高試算表を、貸借対照表（`to` 時点）と損益計算書（`from`〜`to`）の 2 つの表で出す。

- 列: 科目 ・ 期首 ・ 借方 ・ 貸方 ・ 残高（PC）。スマホは 科目 ・ 残高。
  - 期首: 貸借対照表の科目は `from` の前日までの全期間の累計（期首の残高は前の期の仕訳から導く。開始仕訳は作らない、[02 §5](02-accounting-rules.md)）。損益の科目は同じ期の期首から `from` の前日まで。
  - 借方・貸方: `from`〜`to` の合計。残高 = 期首 + 借方 − 貸方 を科目の通常側（資産・費用は借方、負債・純資産・収益は貸方）で表す。小計の行（売上総利益・営業利益・経常利益・税引前当期純利益・当期純利益）は借方・貸方の代わりに「期間」（残高 − 期首）を 1 つ出す。
- 行は残高か期間の動きがある科目だけ（すべて 0 の科目は出さない）。決算書の区分（流動資産 / 固定資産 / 繰延資産 / 流動負債 / 固定負債 / 株主資本 / 売上高 / 売上原価 / 販売費及び一般管理費 / 営業外収益 / 営業外費用 / 特別利益 / 特別損失 / 法人税等）の見出しと小計を出す。
- 貸借対照表の合計行: 資産 合計 / 負債 合計 / 純資産（株主資本の科目 + 前期以前の損益（決算振替前。前の期の収益・費用のうち 3200 に振り替えていない分。第 1 期では出ない）+ 当期純利益）/ 負債・純資産 合計。当期純利益は期首から `to` までの累計。
- 損益計算書の小計: 売上総利益（売上高 − 売上原価）→ 営業利益（− 販管費）→ 経常利益（＋ 営業外収益 − 営業外費用）→ 税引前当期純利益（＋ 特別利益 − 特別損失）→ 当期純利益（− 法人税等）。内部科目（9000）は会社全体で 0 なので表に出さず、0 でなければ警告帯に出す。
- セグメントを選ぶと損益計算書だけが絞られ、貸借対照表は全社のまま（表の上に「貸借対照表は全社の数字です」）。
- 科目の行は総勘定元帳へのリンク（`/reports/ledger?account=<id>` に条件を添える）。補助科目のある科目（現金・普通預金・Stripe 残高・未払金・役員借入金・売掛金など）は行を開くと補助科目ごとの内訳（`<details>`）。
- 恒等式が合わないときの警告帯: 「資産と負債・純資産の合計が n 円合いません。監査ログを確かめてください」。
- 空のとき（期に仕訳がない）: 「この期間に仕訳がありません。取引から登録します」。

## 4. 月次推移 `/reports/monthly`

- 列は期の各月（第 1 期は 5 列、通常 12 列）と 合計。`period` が `custom` のときは `from`〜`to` を含む月だけ。今月 / 今期 の区別は列に影響しない（今月でも期の全月を出す。月を見たいときは試算表）。
- 行は損益の科目を決算書の区分で折り畳む（`<details>`。既定は開いた状態。区分の行に区分の合計）。小計の行: 売上高 計 / 売上原価 計 / 売上総利益 / 販管費 計 / 営業利益 / 営業外収益 計 / 営業外費用 計 / 経常利益 / 特別利益 計 / 特別損失 計 / 税引前当期純利益 / 法人税等 / 当期純利益。
- 各月の当期純利益は、その月を `from`〜`to` にした損益計算書の当期純利益と一致する。合計の列は期（または `from`〜`to`）の損益計算書と一致する（受け入れ条件）。
- セグメントの切替が効く。前年同月は §15.6（第 2 期から）。
- CSV: 科目コード ・ 科目 ・ 各月 ・ 合計（小計の行も含む）。PDF は横向き。

## 5. セグメント損益 `/reports/segments`

- `from`〜`to` の損益を、列 = セグメント（有効なもの。`sortOrder` 順）＋ 合計（セグメントのない損益の行があれば「未設定」の列も）、行 = 収益の科目 → 費用の科目 → 内部取引 で出す。小計: 売上高 計 / 費用 計 / 利益（売上高 − 費用 ± 内部取引）。合計の列の内部取引は常に 0。
- 表の上に利益の横棒（ホームと同じ部品）。セグメント名は「① プラットフォーム」のように番号を添える（共通は番号なし）。
- CSV: 行 × 列。PDF は縦向き。

## 6. 現預金 `/reports/cash`

- 上: `to` 時点の現預金の合計（`isCashLike` の科目の残高の合計。試算表と一致する）と口座のカード。カードは有効な口座のうち現預金の科目に紐づくもの: 名前・種類・残高（口座の補助科目の残高）・最終同期または最終取込の日時（`StripeAccountLink.lastSyncedAt` か最新の `ImportBatch.executedAt`）・未処理の明細 n 件・明細の残高との差異。Stripe の口座は「入金待ち」と添える。
- 明細の残高との差異: `txnDate ≤ to` で `balanceAfter` を持つ最後の明細の残高と、その日の帳簿の残高の差。0 なら「一致」、0 でなければ警告の色で「帳簿の残高が n 円多い（2026/12/31 時点）」（明細の残高が多いときは「明細の残高が …」）。明細がなければ「明細なし」。`Wallet.openingBalance` は取込の照合の起点であり、ここでは使わない（[01 §2](01-domain-model.md)）。
- 折れ線: `from`〜`to` の各日の残高を口座ごとに 1 本、合計を 1 本（SVG。ライブラリは使わない。口座はグレーの濃淡、合計は primary）。凡例は口座名。スマホは高さを抑え、凡例は下。
- 下: 現預金でない口座（カード・役員立替）の表「未払・立替」: 名前・種類・残高（負債側の残高）・未処理 n 件。
- CSV: 口座 × 月末残高（`from`〜`to` の各月）と 合計。PDF は同じ表。

## 7. 仕訳帳 `/reports/journal`

- `from`〜`to` の仕訳を日付順（同じ日付は No. 順）に、1 仕訳 = 見出し行（日付 ・ No. ・ 摘要 ・ 種類 ・ 状態）＋ 行（貸借 ・ 科目 / 補助科目 ・ 借方 ・ 貸方 ・ 税区分と税額 ・ セグメント ・ 取引先 ・ 行の摘要）。状態は 取消済み / 反対仕訳 / 訂正済み を小さな文字で出し、取消済みの行は muted。
- セグメントを選ぶと、そのセグメントの行を持つ仕訳だけ（行はすべて出す）。`status=posted` で取消済みと反対仕訳を除ける（既定はすべて。帳簿は全部見せる）。
- 50 仕訳ごとにページ（`page`）。表の下に期間の借方合計・貸方合計（全ページ）と件数。
- No. は仕訳の詳細 `/entries/[id]`（S3 #4）へのリンク。
- CSV: 1 行 = 1 仕訳行。列: 日付 ・ No. ・ 摘要 ・ 種類 ・ 状態 ・ 行 ・ 貸借 ・ 科目コード ・ 科目 ・ 補助科目 ・ 金額 ・ 税区分 ・ 税額 ・ セグメント ・ 取引先 ・ 行の摘要。PDF は横向きで、ページをまたいでも仕訳の見出しが切れないようにする。

## 8. 総勘定元帳 `/reports/ledger`

- パラメータ `account`（科目 id。無いときは科目の一覧を出して選ばせる）と `sub`（補助科目 id。任意）。上に科目の select（「コード 名前」。動きのある科目を先に、区切って残り）と補助科目のチップ（全部 / 各補助科目）。
- 表: 日付 ・ No. ・ 摘要 ・ 相手科目 ・ 借方 ・ 貸方 ・ 残高。先頭に「繰越」（`from` の前日までの残高。損益の科目は期首から）、末尾に「合計」（期間の借方・貸方）と「残高」。残高は科目の通常側で、一行ごとに累計する（残高の推移）。
- 相手科目は反対側の科目名（補助科目があれば「科目 / 補助」）。反対側が 2 行以上なら「諸口」。
- 行の No. は仕訳の詳細 `/entries/[id]` へのリンク。「試算表へ」で条件を保ったまま戻る。
- セグメントを選ぶと、そのセグメントの行だけを足す（繰越もそのセグメントだけ）。集計（§15.3）からは `partner`（取引先）と `tag`（タグ）の絞り込みも受け、繰越も同じ条件で足す。絞り込み中は表の上にチップ（「取引先: 〇〇 ×」）を出し、× で外す。
- CSV: 日付 ・ No. ・ 摘要 ・ 相手科目 ・ 借方 ・ 貸方 ・ 残高（繰越と合計の行も）。PDF は横向き。

## 9. ホーム `/`

一画面で「お金は今いくらあり、今月はどうか、何をすべきか」（[05 §2.1](05-ui-ux.md)）。スマホでは最初の画面で分かる。時点は今日（期首前なら期首）。#68 で、損益を 1 ブロックにまとめ、やることを 1 つの一覧にし、下端の案内文を外した。

- 最上段（現預金の上、幅いっぱい）: 初月のガイド「はじめの手順」のカード（[10 §3.1](10-settings-and-setup.md)）。全部済むと出ない。差し込みは 1 行（`<FirstMonthGuide />`）。
- 並び（DOM の順 = スマホの順）: 初月のガイド（出るときだけ）→ 現預金 → やること → 損益 → 資金繰り。PC（1024px 以上）は 2 列のグリッドで、左（2fr）に 現預金 と 損益、右（1fr）に やること を 現預金 と 損益 の 2 段にまたがって置き、資金繰り は最下段に幅いっぱい。口座が 5 件のとき、1280px で縦のスクロールが 1 画面＋少しに収まる。
- 現預金（1 枚）: 合計（大きな数字。§6 の合計と同じ）・「YYYY/MM/DD 時点」・「カード未払 n 円 · 役員立替 n 円」（現預金でない口座の残高）と、その下に口座のカード（§6 と同じ中身: 残高・最終同期 / 取込・未処理 n 件・再接続が必要。Stripe は「入金待ち」）。口座のカードは細い線で区切り、PC は 3 列、スマホは 2 列。見出し「現預金 ›」は現預金のタブ（同じ時点）へ。口座がなければ「現預金の口座はまだありません」。
- 損益（1 枚）: 見出し「損益」の右に「今月 | 今期」のセグメント型の切替（リンク。URL の `pl=month|year` が正で、既定は `month`。ほかの値は既定）。その下に期間（今月は月の範囲、今期は「第 n 期 …」）、売上 ・ 費用 ・ 利益（利益は 0 以上のとき primary-ink、マイナスは文字の色のまま）、セグメント別の利益の横棒（最大値を 100% とし、マイナスは track の色）。見出しのリンクは選んだ側の試算表（`/reports/trial-balance?period=month|year`）。切り替えると数字・棒・リンク先が一緒に変わる。
- やること（1 枚の一覧）: 行 = 件数か日付のバッジ ・ 文 ・ 「›」で、行全体がその画面への入口。元は `HOME_TODO_SOURCES`（件数と文を返す各レーンの関数。ホームは数えない）の順に:
  1. 未処理の明細 n 件 → `/statements`（S5 `countPendingWalletTransactions`）
  2. 受信箱の証憑 n 件 → `/documents`（S6 `countInboxDocuments`。未紐づけ、または取引年月日・金額・取引先のどれかが空。[13 §3.2](13-documents.md)）
  3. 銀行 API の再接続 n 件 → 口座の接続の画面（#17。[19 §1.2](19-bank-api.md)）

## 10. 書き出しとバックアップ `/settings/export`

1 ページに節で並べる。各節は GET のフォームで、「書き出す」でブラウザのダウンロードになる（`/settings/export/download?kind=…`）。

## 11. 形式

### 11.1 freee の仕訳インポート形式

freee 会計の「仕訳データのインポート」のテンプレート（借方と貸方の列が分かれた形式）。1 行目が見出しで先頭の列は `[表題行]`、2 行目以降の先頭の列は `[明細行]`。列（この順）:

`[表題行]` ・ 日付 ・ 伝票番号 ・ 決算整理仕訳 ・ 借方勘定科目 ・ 借方科目コード ・ 借方補助科目 ・ 借方取引先 ・ 借方取引先コード ・ 借方部門 ・ 借方品目 ・ 借方メモタグ ・ 借方セグメント1 ・ 借方セグメント2 ・ 借方セグメント3 ・ 借方金額 ・ 借方税区分 ・ 借方税額 ・ 貸方勘定科目 ・ 貸方科目コード ・ 貸方補助科目 ・ 貸方取引先 ・ 貸方取引先コード ・ 貸方部門 ・ 貸方品目 ・ 貸方メモタグ ・ 貸方セグメント1 ・ 貸方セグメント2 ・ 貸方セグメント3 ・ 貸方金額 ・ 貸方税区分 ・ 貸方税額 ・ 摘要

- 1 仕訳は同じ伝票番号（= 仕訳の No.）の行にまとまる。i 行目に i 番目の借方の行と i 番目の貸方の行を置き、片側が尽きたらその側の列は空にする（複合仕訳）。
- 日付は `YYYY/MM/DD`。決算整理仕訳は `kind` が `adjusting` / `closing` のとき `1`、それ以外は空。
- 科目は名前とコード（4 桁）の両方、補助科目は名前、取引先は名前、セグメント1 はセグメントの名前、メモタグはタグ名（複数は `|` 区切り）。部門・品目・セグメント2・3 は空。
- 金額は税込（税込経理）または計上額（税抜経理）の整数、税額は行の `taxAmount`、税区分は §11.4 の対応表の freee の名前。
- 摘要は仕訳の摘要。取消済みの仕訳は末尾に「（取消済み）」、反対仕訳は台帳の摘要（「取消 No.n: …」）のまま。
- 文字コードは UTF-8（BOM 付き）か Shift_JIS。CRLF。

### 11.2 弥生の仕訳形式

弥生会計の「仕訳データのインポート」（仕訳日記帳の 25 項目、見出し行なし）。列（この順）:

識別フラグ ・ 伝票No. ・ 決算 ・ 取引日付 ・ 借方勘定科目 ・ 借方補助科目 ・ 借方部門 ・ 借方税区分 ・ 借方金額 ・ 借方税金額 ・ 貸方勘定科目 ・ 貸方補助科目 ・ 貸方部門 ・ 貸方税区分 ・ 貸方金額 ・ 貸方税金額 ・ 摘要 ・ 番号 ・ 期日 ・ タイプ ・ 生成元 ・ 仕訳メモ ・ 付箋1 ・ 付箋2 ・ 調整

- 借方 1 行・貸方 1 行の仕訳は識別フラグ `2000` の 1 行。それ以外は伝票として 1 行目 `2110`・中間 `2100`・最終行 `2101`（行の組み方は freee と同じで、片側がない行は科目を空・金額を `0`・税区分を「対象外」にする）。
- 伝票No. は仕訳の No.、決算は `adjusting` / `closing` のとき「本決」、取引日付は `YYYY/MM/DD`、タイプは `0`、生成元は空、仕訳メモは「No.n ・ 登録済み / 取消済み / 反対仕訳」、付箋は `0`、調整は `no`。
- 摘要は 64 桁（半角換算）で切る。部門は空。
- 税区分は §11.4 の弥生の名前、税金額は行の `taxAmount`。
- 文字コードは Shift_JIS（CP932）が既定。CRLF。CP932 で表せない文字（絵文字・一部の漢字）は「?」になるので、画面の説明で UTF-8 を選べることを案内する。

### 11.3 beancount

```
option "title" "架空商会株式会社"
option "operating_currency" "JPY"

2026-11-02 open Assets:1100-普通預金:架空銀行-普通 JPY
2026-11-02 open Equity:3000-資本金 JPY

2026-11-02 * "資本金の払込" ^e1
  no: 1
  kind: "opening"
  source: "manual"
  Assets:1100-普通預金:架空銀行-普通   50000 JPY
  Equity:3000-資本金                  -50000 JPY
```

- 科目の写像: 資産 → `Assets`、負債 → `Liabilities`、純資産 → `Equity`、収益 → `Income`、費用 → `Expenses`、内部 → `Equity:Internal`（会社全体で 0 なので損益に出さない）。科目は `<コード>-<名前>`、補助科目はその下に `<名前>`。名前の空白と beancount で使えない文字（`:` など）は `-` に置き換える。科目の要素はコードで始まり、補助科目の要素が半角の小文字で始まるときは大文字にする（beancount は要素の先頭に半角の小文字を許さない。漢字・かな・数字は許す）。
- 期（`from`）より前の仕訳は書き出さず、`from` の日付の「期首残高」の取引 1 つにまとめる（貸借対照表の科目はその残高、前の期の損益の分は `Equity:Opening-Balances`）。全期間の書き出しでは出ない。
- `open` は会社の設立日（`Company.foundedOn`）で、書き出しに現れる科目と補助科目の分だけ（補助科目を使う科目は親の科目も開く。残高の表明は親の科目に対して行う）。
- 取引は日付順に `*` で、第 1 項は取引先（仕訳の最初の行の取引先。無ければ省略）、第 2 項は摘要。リンク `^e<No.>`（反対仕訳は取消した仕訳の `^e<No.>` も付ける）。メタデータ `no`、`kind`、`source`、取消済みなら `status: "voided"`、反対仕訳なら `reversal_of: <No.>`。各 posting のメタデータに `segment`（セグメントのコード）、`tax`（税区分のコード）、`tax_amount`（0 でないとき）、`line`（行の摘要があれば）。
- 金額は借方が正、貸方が負の JPY の整数。
- 末尾に `to` の翌日付の `balance`（貸借対照表の科目ごとの残高。貸方の科目は負）。bean-check がこの残高を取引から再計算するので、第二の検算になる。
- `bean-check` を通ることがテスト（フィクスチャの書き出しをゴールデンにし、`bean-check` がローカルにあれば実行する）。

## 15. 集計 `/reports/breakdown`（v2 #50）

freee の「収益レポート / 費用レポート」「集計表」に当たる。収益か費用を、取引先・タグ・科目・セグメントのどれかの軸で月別に並べ、「どの顧客からいくら」「どの SaaS にいくら」を一覧で見る。

- パラメータ（§1 の期間とセグメントに加えて）: `axis`（`partner` 取引先 / `tag` タグ / `account` 科目 / `segment` セグメント。既定 `partner`）、`side`（`revenue` 収益 / `expense` 費用。既定 `revenue`）、`top`（`10` / `20` / `50` / `all`。既定 `10`）、`sort`（`amount` 金額の大きい順 / `name` 名前順。既定 `amount`）、絞り込みの `partner`・`tag`（ドリルダウンで付く。§15.3）。条件のフォームに 軸（select）・収益 / 費用（セグメント型ボタン）・上位（select）・並び（select）を足す。
- 対象の行: 収益は `revenue` の科目、費用は `expense` の科目の仕訳行。内部取引（9000）は含めない（試算表の損益計算書と同じ）。金額は科目の通常側（収益は貸方 − 借方、費用は借方 − 貸方）。取消済みの仕訳と反対仕訳はそのまま足して 0 になる。対象の期の決算振替とその取消は除く（§1）。
- 列: 1 列目が軸の名前（科目はコードつき）、続いて期の各月（`custom` は範囲を含む月だけ。§4 と同じ）、合計、構成比（合計の列に対する割合。整数の演算で小数 1 桁に丸め、表示だけ。合計が 0 以下なら「—」）。
- 行の合計（列ごとの合計）を最後に出す。対象の行がないときは EmptyState「この期間に収益（費用）の仕訳がありません」。
- 役割（[23 §1](23-users-and-expenses.md)）: 集計は報告の下なので閲覧も見られ、CSV / PDF も書き出せる（`/reports/export` は閲覧以上）。取引先の詳細（§15.5）は設定の下なので、閲覧には proxy が権限の画面を出す。

### 15.1 軸ごとの行

- 取引先: 行の取引先 → その行の補助科目の取引先 → 仕訳のほかの行の取引先が 1 つに決まるときはそれ、の順で決める。決まらない行は「取引先なし」。3 つ目は損益の行（収益・費用）にだけ使う（伝票で売掛金の行にだけ取引先を入れたときに、売上の行もその取引先に数えるため）。
- タグ: 行のタグごと。タグが 2 つ以上ある行は、それぞれのタグに数える（freee のメモタグと同じ）。タグのない行は「タグなし」。重なりがあるときは表の上に「複数のタグがついた行は、それぞれのタグに数えています（重なり n 円）」を出す。合計の行は重なりを数えない（試算表と一致する）。
- 科目: 科目ごと。
- セグメント: セグメントごと（番号つきの名前は §5 と同じ）。セグメントのない行は「未設定」。この軸ではセグメントの切替を出さない（§5 と同じ）。

### 15.2 並びと上位

- 並び: 合計の大きい順（同じなら名前順）か、名前順（科目はコード順、セグメントは `sortOrder` 順）。
- 上位 n 件を出し、残りは「その他（m 件）」の 1 行にまとめる（`all` はまとめない）。「取引先なし」「タグなし」「未設定」と「その他」は並びに関わらず末尾（「なし」→「その他」の順）で、上位の件数に数えない。

### 15.3 ドリルダウン

- 科目の軸: 行 → 総勘定元帳（`/reports/ledger?account=<id>` に期間・セグメントと絞り込みの `partner` / `tag` を添える）→ 仕訳。
- 取引先・タグ・セグメントの軸: 行 → 同じ期間の集計を科目の軸にして、その値で絞る（`axis=account&partner=<id>` / `tag=<id>` / `segment=<id>`）→ 科目の行から総勘定元帳 → 仕訳。「取引先なし」「タグなし」は `partner=none` / `tag=none`。「未設定」のセグメントと「その他」はリンクしない。
- 絞り込み中は、表の上に「取引先: 架空クラウド株式会社 ×」のチップを出し、× で外す。
- 総勘定元帳の取引先の絞り込みは §15.1 と同じ決め方（`none` は取引先なし）、タグの絞り込みは「そのタグがある行」（`none` はタグのない行）。総勘定元帳の期間の動き（借方 − 貸方を通常側で）は、集計のその科目・その値の合計と一致する。

### 15.4 書き出し

- CSV: 軸の名前・科目コード（科目の軸だけ）・各月・合計・構成比。「なし」「その他」と合計の行も含む。ファイル名は `breakdown-<axis>-<side>_<from>-<to>.csv`。PDF は横向き（月が 12 列になる）。題名は「集計（取引先別・収益）」のように軸と収益 / 費用を入れる。

### 15.5 取引先の詳細 `/settings/partners/[id]`

- 設定 › 取引先の一覧の行の末尾に「詳細」のリンクを足して開く。PageHeader は取引先の名前、戻るは取引先の一覧。
- 上: 区分・カナ・登録番号・既定の科目・既定のセグメント・既定の税区分（読み取りだけ。編集は一覧で行う）。
- 小さな表「第 n 期」（今日を含む期。期首前なら第 1 期）: 収益 ・ 費用 ・ 未入金 ・ 未払。
  - 収益・費用: §15.1 の決め方でこの取引先に数える行の、期首から期末まで（今日より後の日付の仕訳も含む）の合計。決算振替は除く。
  - 未入金: 売掛金（1200）・未収入金（1250）の今日時点の残高（借方を正）。未払: 買掛金（2000）・未払金（2100）・未払費用（2110）の今日時点の残高（貸方を正）。どちらも、行の取引先か補助科目の取引先がこの取引先の行だけを足す（仕訳のほかの行からは決めない。カードの未払金はカード会社への債務で、買った先のものではないため）。
  - 数字はリンク: 収益・費用 → `/reports/breakdown?axis=account&side=revenue|expense&partner=<id>`（その期）。未入金・未払は科目ごとの内訳の行（残高のある科目だけ）を出し、各行 → その科目の総勘定元帳を `partner=<id>` で。
  - 「仕訳を見る」→ `/entries?partner=<id>`（取引の一覧の絞り込み、[11 §3](11-transactions.md)）。
- 取引先のない帳簿や仕訳のない取引先でも、表は 0 で出す。

### 15.6 月次推移の前年同月

- 月次推移の条件に「前年同月」の切替（`compare=prior`）を足す。前の期があるときだけ出す（第 1 期では出さない）。
- 前年同月 = 列の月の 1 年前の同じ月の損益（その月を含む期の決算振替を除く）。帳簿が始まる前の月と、前の期の範囲の外の日は数えず、月がまるごと帳簿の前なら「—」。合計の列の前年は、前年の各月の合計。
- オンのとき、各月と合計のセルに 2 段目として前年の金額を muted の小さな字で出す。CSV は各月と合計の右に「YYYY/MM 前年」の列を足す。PDF は前年の列を出さない（横向きでも 24 列は読めないため）。

### 15.7 データと層

- `packages/reports/src/breakdown.ts`: `buildBreakdown(source, period, { axis, side, top, sort, partnerId, tagId })`、`partnerOfLine(entry, line, index, { fromOtherLines })`（§15.1。総勘定元帳と取引先の詳細が共有する）、`buildPartnerSummary(source, partnerId, { today })`（§15.5）、`breakdownCsvRows(report)`。

- テスト: フィクスチャで、取引先別・科目別・セグメント別の合計と、タグの重なりがないときのタグ別の合計が、試算表の損益計算書の収益・費用と一致する。タグの重なりの額、「取引先なし」「タグなし」「未設定」、上位 n と「その他」、両方の並び、取引先の決め方（行 → 補助科目 → 仕訳のほかの行、決まらないとき）、絞り込み、取引先で絞った総勘定元帳の期間の動き = 集計の値、未入金・未払（カードの未払金を数えない）、前年同月（第 2 期の 4 月は「—」、11 月は第 1 期の 11 月）、CSV のゴールデン。

## 16. 受け渡しパッケージ `/settings/export/package`（#55）

税理士や将来の経理担当に、期を指定して 1 つの zip で渡す（[07 §7](07-operations.md)）。中身はすべて既存の書き出しと同じ関数で作り、形式を増やさない。

### 16.1 画面

設定 › 書き出しとバックアップ に節「受け渡しパッケージ」を足し（追記だけ）、`/settings/export/package` を開く入口にする。

- 条件の GET フォーム: 期（第 n 期の select。既定は「今日が前の期の期末から 3 か月以内ならその前の期、それ以外は今日を含む期」。[17 §2](17-financial-statements.md) と同じ）、「証憑のファイルを含める」（チェック。既定は外す）。
- 中身の一覧（§16.2 の表を、その期で実際に入るものだけ。締めていない期は「決算書は締めた期だけ入ります」）。証憑は「n 件・約 n MB」（その期の証憑の `byteSize` の合計）を出す。
- 「書き出す」: 大きさの見積り（§16.4）が上限以下ならその場で zip をダウンロード。超えるときは「作成を依頼」になり、ジョブで作る。依頼すると下の「作成した受け渡しパッケージ」に「作成中」で出る。
- 作成した受け渡しパッケージ: 監査ログ `export.package` の直近 10 件の依頼（日時 ・ 期 ・ 証憑を含むか ・ 状態〔作成中 / 作成済み / 失敗〕・ 大きさ ・ 依頼者）。作成済みの行に「ダウンロード」（`/settings/export/package/download?request=<id>`。署名付き URL への 302）。作成中が 30 分を超えたら「失敗した可能性があります。もう一度依頼してください」。
- スマホ（768px 未満）でも操作できる（表は 期・状態・ダウンロード の 3 列に畳む）。320px で欠けない。
- 閲覧（#21 の viewer）以上が取れる（[決定](../decisions/2026-10-29-handover-package-viewer.md)）。画面は proxy が `/settings/export/*` を閲覧に通し、依頼の Server Action とダウンロードの route は入口で `authorizeAction("viewer")` / `authorizeRoute("viewer")`。

### 16.2 zip の中身

ファイル名は ASCII（`<from>` `<to>` は `YYYYMMDD`）。zip の名前は `handover_fy<n>_<from>-<to>.zip`。zip の中の順は 帳簿・決算整理・決算書 → 証憑のファイル → `documents/index.csv` → `README.txt` → `manifest.json`（索引の「パッケージ内のファイル」と README の SHA-256 は、取れた証憑が決まってから書くため）。

### 16.4 その場で作るか、ジョブで作るか

- 見積り = 証憑を含めるときの証憑の `byteSize` の合計 ＋ 帳簿の分（2 MB とみなす）。**20 MB 以下**ならその場で作ってダウンロード（画面のサービスの応答の上限 32 MiB・タイムアウト 60 秒に収める）。超えるときはジョブ。
- ジョブ: 画面のサービスが Cloud Tasks のキュー（S8 の `niho-finance-manual`）に、ジョブ用サービスの `/api/jobs/handover-package` への POST を積む（OIDC は Scheduler と同じサービスアカウント、audience はジョブ用サービスの URL。本文は `{ requestId, fiscalYearId, includeDocuments, requestedBy }`）。ジョブは同じ関数で zip を作り、バックアップバケットの `packages/<作成日時>_fy<n>_<requestId>.zip` に置く（保持ポリシーの下で残る）。証憑は 1 件ずつ読み、zip はストリームで書いてメモリに全体を持たない。
- ダウンロード: `/settings/export/package/download?request=<id>` が監査ログの「作成済み」の行のキーを確かめ、V4 の署名付き GET URL（10 分、`response-content-disposition` に zip の名前）へ 302。
- ローカル（`NIHO_FINANCE_TASKS_QUEUE` がない）: 依頼はその場でジョブの関数を動かし、`NIHO_FINANCE_BACKUP_DIR` に置いて、ダウンロードは本体を返す。本番でキューがないときは証憑のファイルを外してその場で作り、README の注意にその旨を書く。その場のダウンロードは zip をメモリに組んでから返す（20 MB 以下なので）。証憑が保存先にない・大きすぎるときは「（取得できませんでした）」、それ以外の保存先のエラーはパッケージ全体を失敗にする（S7 の証憑一式と同じ）。
- 配備（S8 の `scripts/` に追記）: 画面のサービスに `NIHO_FINANCE_TASKS_QUEUE`・`NIHO_FINANCE_JOB_URL`・`NIHO_FINANCE_JOB_SERVICE_ACCOUNT`・`NIHO_FINANCE_BACKUP_BUCKET` を渡す。実行用のサービスアカウントに、キューへの `roles/cloudtasks.enqueuer` と、Scheduler のサービスアカウントへの `roles/iam.serviceAccountUser`（タスクに OIDC を付けるため）。費用はタスク数件で 0 円。
