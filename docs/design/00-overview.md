## 2. 事業構造とセグメント

帳簿は会社全体で 1 つですが、損益は次の 3 つの事業（セグメント）に分けて見られるようにします。すべての仕訳行にセグメントを持たせ、共通費は「共通」に置きます。

| セグメント | 内容 | 主な収入 | 主な費用 |
| --- | --- | --- | --- |
| ① プラットフォーム | NIHO アプリの運営 | プラットフォーム手数料、利用料（Stripe platform アカウント） | GCP・各種 SaaS・AI API・開発費 |
| ② 直営拠点 | NIHO kamakura などの直営拠点の運営 | 会費・ドロップイン・体験（拠点の Stripe アカウント）、現金 | 家賃・水道光熱・備品・消耗品 |
| ③ 受託開発 | 個別の受託開発 | 請求書による売上（銀行振込が中心） | 外注費・業務委託費 |
| 共通 | 会社運営 | — | 役員報酬・社会保険・税金・会計/法務・通信 |

## 3. 目的と成功条件

毎月の経理を短時間で確実に終え、現預金と損益を常に把握し、決算書を自分たちで作れる状態を目指します。

| 目的 | 成功条件（測れる形） |
| --- | --- |
| 月次が軽い | 月初 5 営業日以内に「未処理の明細 0 件・未紐づけの証憑 0 件・月次の締め」が終わる。所要 1 時間以内 |
| 数字が見える | ホームを開けば、口座ごとの残高、今月と今期のセグメント別 PL、3 か月先の資金繰りが分かる |
| 決算ができる | 第 1 期末に貸借対照表・損益計算書・株主資本等変動計算書・個別注記表を出せる。申告用に財務諸表 CSV と勘定科目内訳の元データを出せる |
| 法令を満たす | 電子取引データの保存要件（真実性・検索性）を満たし、帳簿と証憑を 7 年（欠損金がある年は 10 年）保存できる。インボイス登録した場合に適格請求書を発行・保存できる |
| 人に渡せる | 税理士や将来の経理担当が読める形（仕訳帳・総勘定元帳・証憑一式）でいつでも書き出せる |
| 壊れない | 仕訳は改変できず、すべての変更が監査ログに残り、日次バックアップから復元できる |

## 4. 範囲

### v1（設立〜第 1 期の月次運用。2026-11〜2027-01）

- 事業所・会計期間・勘定科目（標準テンプレート）・税区分・セグメントの初期設定と、設立時の開始仕訳（資本金の払込、創立費、役員立替）
- 口座: 銀行・クレジットカード・現金・Stripe（2 アカウント）・役員立替
- 明細の取込: 銀行とカードは CSV、Stripe は API。重複の排除。未処理の明細を「登録・振替・無視」で片付ける画面と自動登録ルール
- 取引の手入力（収入・支出・振替・振替伝票）
- 証憑の保存: アップロード（PC・スマホのカメラ）、日付・金額・取引先での検索、改ざん防止、仕訳への紐づけ
- 帳票: 仕訳帳、総勘定元帳、試算表（BS/PL）、月次推移、セグメント別 PL、現預金の残高と推移
- 月次の締め（ロック）と監査ログ
- エクスポート: 仕訳 CSV（freee / 弥生 形式）、beancount テキスト、証憑一式
- 配備・認証・日次バックアップ・税務カレンダー

### v2（第 1 期の決算と請求。2027-02〜2027-06）

- 固定資産台帳と減価償却、決算整理（前払・未払・貯蔵品・法人税等）、期末の締めと翌期の開始残高
- 決算書 PDF（BS・PL・株主資本等変動計算書・個別注記表）、財務諸表 CSV（国税庁形式）、勘定科目内訳明細の元データ
- 消費税の集計（税区分別・課税/免税の切替）、インボイス登録番号の照合
- 見積書・納品書・請求書（適格請求書の様式、PDF、メール送付、入金の消込、必要なら Stripe の支払いリンク）
- 資金繰りの予測（定期的な支払い・税金の予定）
- 銀行 API の直結（口座を持つ銀行が API を提供している場合）、領収書の自動読み取り（LLM）

### v3（2027 年度〜。人が増えたら）

- 役員報酬・給与（1〜2 名）、社会保険、源泉徴収、年末調整、法定調書
- 経費精算（社員・業務委託の立替）
- 複数ユーザーと権限（経理担当、税理士の閲覧）
- 申告書（別表）のドラフト、または税理士連携の強化

### 範囲外

- NIHO アプリの会員向け請求・決済（アプリ側が担当。本システムは結果を取り込む）
- 在庫・原価計算、多通貨、連結、部門別予算
- 他社の拠点（NIHO アプリ上で他のホストが運営する拠点）の帳簿

## 5. 設計の方針

- 台帳が中心: 画面も連携もすべて「仕訳」に落ちる。残高・レポートは仕訳から導出し、別に保持しない（derive, don't sync）。
- 不変の帳簿: 登録した仕訳は書き換えない。訂正は反対仕訳と新しい仕訳。削除は論理削除。
- 明細ファースト: 日々の入力の大半は「取り込んだ明細を片付ける」操作。手入力は例外。
- 証憑は検索できる形で永久保存: 電子帳簿保存法の検索要件（日付・金額・取引先）を保存時に満たす。
- 小さく正しく: 1 社・JPY・数人。汎用 SaaS の抽象化（多事業所・多通貨・権限体系）を先取りしない。
- 公開コード・非公開データ: コードと汎用文書は公開リポ、実データ・設定・秘密は非公開側。
- 既存の技術で作る: TypeScript、Next.js、Prisma、PostgreSQL、GCP Cloud Run（NIHO アプリと同じ）。

## 6. 用語

| 用語 | 意味 |
| --- | --- |
| 口座（wallet） | お金の出入りを記録する器。銀行・カード・現金・Stripe・役員立替 |
| 明細（wallet transaction） | 口座から取り込んだ 1 行。登録・振替・無視のいずれかで片付ける |
| 取引 / 仕訳（journal entry） | 複式簿記の 1 伝票。複数の行（借方・貸方）を持つ |
| 証憑（document） | 領収書・請求書・契約書・明細書などの原本（画像・PDF） |
| セグメント | ①プラットフォーム ②直営拠点 ③受託開発 共通 の事業区分 |
| 締め | ある日付以前の期間を変更不可にすること。月次と期末 |
