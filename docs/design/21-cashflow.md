# 21. 定期取引と資金繰り（v2 #19・#54 の画面仕様）

[05 画面と体験](05-ui-ux.md) §2.1・§2.5・§2.8 と [01 ドメインモデル](01-domain-model.md) §7 の詳細。v2 の Issue #19 で作る「設定 › 定期取引」、ホーム下段の 90 日の線、「報告 › 資金繰り」のタブと、それを支える予測の計算、#54 で作る予定日の登録（§10。1 クリックの登録・二重登録の防止・明細の推定・取引テンプレート）を定めます。定期取引からの仕訳の自動登録、法人税等の予定額の計算（#14）、請求と入金の消込（#16）、税務の期限の生成と通知（S8 #9）は範囲外です。決定の記録は [資金繰りの予測の規則](../decisions/2026-10-28-cashflow-forecast-rules.md)。

## 1. 共通の決まり

- 予測は毎回導出する（derive, don't sync。[00 §5](00-overview.md)）。予測の結果や日ごとの残高を DB に持たない。入力は「登録済みの仕訳」「定期取引」「納付の期限」「請求」で、どれも画面を開くたびに読む。
- 線は**現預金の合計 1 本**（`isCashLike` の科目の残高の合計。[14 §6](14-reports.md) の合計と同じ）。口座ごとの線は描かない。Stripe の入金や現金の預入のように現預金の中で口座間を動くお金があり、口座ごとに描くと「銀行が 0 を割る」ような誤った警告になるため。
- 起点はホームと同じ日（今日。帳簿の始まる前なら期首。[14 §9](14-reports.md)）。期間は起点から 90 日後まで（91 点）。起点の値はホームの現預金の合計と一致する。
- 日付は名目のまま使う。土日祝で引落しや支払がずれる分は動かさない（日単位の予測なので、ずれは数日以内）。
- 起点の日に発生する定期取引は数えない（その日の分は仕訳か取り込む明細に入るものとする）。起点より前に発生したはずで帳簿にまだない分（取り込んでいない明細）も数えない。報告のタブに「起点は登録済みの仕訳の残高です。取り込んでいない明細の分はずれます」と添える。
- 起点より後の日付で登録した仕訳のうち、同じ日に「口座の科目」と「定期取引の科目」の両方を持つものがあれば、その日の定期取引は登録済みとして数えない（支給日の前に確定した給与や、先日付で登録した家賃を二重に数えない）。数えなかった件数は注記に出す。
- 金額は整数の円（`bigint`）。画面は 3 桁区切り・右揃え・tabular で、単位「円」は見出しに置く。マイナスは記号で表し赤で塗らない。赤（danger）は「0 円を割る」の警告だけに使う（[05 §3](05-ui-ux.md)）。
- 予測は仕訳を登録しない。定期取引から仕訳を作るのは §10 の「登録」（人が押す 1 クリック）だけで、自動では登録しない。
- 文言: 節とタブは名詞句（定期取引 / 資金繰り / 予定の一覧 / 入っていないもの）、ボタンは結果の動詞（追加 / 保存 / 無効にする / 有効にする）。内部の識別子や enum を見せない。

## 2. 定期取引 `RecurringItem`

家賃・サブスク・役員報酬（差引支給額）・カードの引落し・保険料など、毎月または毎年決まって起きる入出金。給与の納付と法人税等は額つきの期限として入るので定期取引にしない（§3.3）。1 件は「口座の科目 ⇄ 科目」の 1 本の仕訳の型として扱う（§3.2）。表と列は S1 の schema で揃っているので、列は足さない。

| 項目 | 画面 | 規則 |
| --- | --- | --- |
| name | 名前 | 必須。1〜60 字（例: 家賃、GCP、役員報酬、社会保険料、カードの引落し） |
| amount | 入出金・金額 | 画面は「入金 / 出金」と正の金額（1〜999,999,999,999 円）。保存は口座から見た符号つき（入金が正）。0 は不可 |
| frequency | 周期 | 毎月 / 毎年 |
| monthOfYear | 月 | 毎年のときだけ必須（1〜12）。毎月のときは保存しない（null） |
| dayOfMonth | 日 | 必須（1〜31）。31 は「末日」と表示する。その月にない日（2 月 30 日など）はその月の末日 |
| startDate | 開始日 | 必須。既定は今日 |
| endDate | 終了日 | 任意。開始日以後。空欄なら終わりなし |
| walletId | 口座 | 必須（有効な口座）。DB は null を許すが画面からは作らない |
| accountId | 科目 | 必須（有効な科目）。口座の科目と同じ科目は不可（借方と貸方が同じ仕訳になる） |
| partnerId | 取引先 | 任意 |
| segmentId | セグメント | 任意。既定は口座の既定セグメント |
| taxCategoryCode | 税区分 | 任意（明細の推定と将来の仕訳の型のため。予測には使わない） |
| note | メモ | 任意。500 字まで |
| isActive | 状態 | 有効 / 無効。削除はなく「無効にする」。無効の定期取引は予測に入れない |

### 2.1 発生日の規則

- 毎月: 開始日の月から毎月 1 回、その月の `dayOfMonth` 日（ない日は末日）。
- 毎年: `monthOfYear` 月の `dayOfMonth` 日（ない日は末日）に年 1 回。
- 発生日 `d` を数えるのは `開始日 ≤ d`、かつ終了日があれば `d ≤ 終了日`、かつ `起点 < d ≤ 起点 + 90 日` のときだけ。開始日の月でも、開始日より前の日なら数えない（1/15 開始・毎月 10 日 → 初回は 2/10）。
- 例: 毎月 31 日（末日）は 11/30・12/31・1/31・2/28（閏年は 2/29）。毎年 2 月 29 日は平年は 2/28。

### 2.2 一覧の表示

- 周期と日: 「毎月 25 日」「毎月 末日」「毎年 5 月 31 日」。
- 終了日: 空欄なら終わりなし。終了日を過ぎたものは状態の隣に muted で「終了」。
- 入出金・金額: 入金は通常の色、出金は記号つき（`-110,000`）。

## 3. 予測の入力

### 3.1 入力と欠けるときの注記

| 入力 | 元 | 線への入り方 | 欠けるときの注記（「入っていないもの」） |
| --- | --- | --- | --- |
| 起点の現預金 | 登録済みの仕訳（`isCashLike` の科目、起点の日まで） | 起点の値 | — |
| 起点より後の日付で登録した仕訳 | 登録済みの仕訳（`起点 < 日付 ≤ 90 日後`） | その日に現預金の科目の増減 | — |
| 定期取引 | 設定 › 定期取引（§2） | 発生日に §3.2 の増減 | 有効な定期取引が 0 件: 「定期取引がまだありません。家賃や役員報酬を登録すると線に入ります」（設定 › 定期取引 への入口） |
| 税金・社会保険の納付 | `CalendarItem` の未完了の納付の期限（§3.3）と、その金額（源泉所得税・住民税・社会保険料は確定した給与から〔[22 §7.2](22-payroll.md)〕、法人税等は決算整理の概算から〔[16 §12](16-year-end.md)〕導く） | 金額があれば期日に出金。金額がなければ線は動かさず、期日に印だけ付ける | 期限の暦がない（`CalendarItem` が 1 件もない）: 「税金・社会保険の期限: まだありません」。金額のない期限が期間内にある: 「金額未定の納付 n 件は印だけです。金額は定期取引に登録すると線に入ります」 |
| 未入金の請求 | 発行・送付した請求書の残高（[18 請求](18-invoicing.md)。下書き・入金済み・無効は除く） | 支払期日に入金。期日を過ぎたもの（起点の日が期日のものを含む）と期日のないものは入れない | 期日を過ぎたものがある: 「期日を過ぎた未入金 n 件 n 円は入れていません」。期日のないものがある: 「期日のない未入金 n 件 n 円は入れていません」 |
| 未払の請求 | 受け取った請求書の未払の残り（支払〔[25](25-payables.md)、#48〕の支払期日と残り） | 支払期日に出金。期日を過ぎたものと期日のないものは起点の翌日に出金（保守的に早めに見る） | 接続済み |
| カードの未払 | カードの口座の残高（起点の日） | 入れない（引落しは定期取引で表す。§3.2） | 有効なカードの口座に未払があり、それを引き落とす定期取引（§3.2 の「カードの引落し」）がない: 「{口座名} の未払 n 円は入っていません。引落しを定期取引（口座: 銀行、科目: 未払金）に登録すると線に入ります」 |
| 現預金を動かさない定期取引 | 定期取引のうち §3.2 で増減が 0 のもの | 入れない | 1 件以上: 「現預金を動かさない定期取引 n 件（カード払いなど）は線に入れていません」 |
| 口座のない定期取引 | `walletId` が null の定期取引（画面からは作らない） | 入れない | 1 件以上: 「口座のない定期取引 n 件は線に入れていません」 |
| 登録済みの定期取引 | 同じ日・同じ 2 つの科目の仕訳がある発生（§1） | 入れない（仕訳の方を数える） | 1 件以上: 「登録済みの取引と同じ日・同じ科目の定期取引 n 件は、二重に数えていません」 |

- 未接続（`null`）と「接続していて 0 件」を区別する。未接続の入力は注記に出し、0 件の入力は出さない。
- 期限の暦は S8（#9）、未入金の請求は請求（#16）の `listInvoices`、未払の請求は支払（#48）の `listPayablesForCashflow`、給与の納付の額は給与（#20）の `listPayrollSchedule`、法人税等の予定額は決算整理（#14）の `loadCorporateTaxEstimate` から繋いである。中間申告の額はまだない（印だけ）。接続は `packages/db/src/recurring.ts` の `loadCashflowInputs` で行い、予測の関数（`packages/reports`）は変えない。

### 3.2 定期取引の現預金への効き方

定期取引 1 件を「口座の科目 ⇄ 科目」の仕訳とみなし、現預金の科目にかかる側だけを足す。

`現預金の増減 = （口座の科目が現預金 ? 金額 : 0） − （科目が現預金 ? 金額 : 0）`（金額は口座から見た符号つき）

| 例 | 口座 | 科目 | 入出金 | 現預金の増減 |
| --- | --- | --- | --- | --- |
| 家賃 | 銀行 | 地代家賃 | 出金 110,000 | −110,000 |
| 売上の入金（受託の毎月の保守） | 銀行 | 売上高 | 入金 300,000 | +300,000 |
| サブスク（カード払い） | カード | 通信費 | 出金 3,300 | 0（カードの未払が増えるだけ） |
| カードの引落し | 銀行 | 未払金 | 出金 50,000 | −50,000 |
| Stripe の入金 | 銀行 | Stripe 残高 | 入金 200,000 | 0（現預金の中の移動） |
| 役員立替の精算 | 銀行 | 役員借入金 | 出金 20,000 | −20,000 |

- カード払いの定期取引は線を動かさない。カードのお金が出ていくのは引落しの日なので、引落しを銀行の定期取引（科目: 未払金）として登録する。これでカード払いと引落しを二重に数えない。
- 「カードの引落し」の判定（§3.1 の注記）: 有効な定期取引のうち、科目がそのカードの口座の科目で口座が現預金のもの、または口座がそのカードで科目が現預金のもの。

### 3.3 納付の期限

- `CalendarItem` のうち、未完了（`completedAt` が null）で期日が `起点 < 期日 ≤ 90 日後` のもので、種類が納付（`kind = payment`）か、申告と納付を兼ねる規則（`ruleKey` が `annual.tax-return`・`annual.interim-return`。S8 の規則のキーは公開後に変えない）。
- 期限の行は S8（#9）が会計期間から、給与（#20）が支給の確定から生成する。行がまだ 1 件もないときは未接続として注記する。
- 金額は期限の行にない（derive, don't sync）。給与の確定が作る期限（`ruleKey` が `payroll.`）には `listPayrollSchedule` の予定額を付ける。予定額が 0 の期限は払うものがないので入れない。S8 の申告と納付（`annual.tax-return`）には法人税等の予定額を付ける: 決算整理の概算（`loadCorporateTaxEstimate`）のうちまだ計上していない額（`suggested`）＋ 起点の日の未払法人税等（2120）の残高。期末の計上の前は概算の全額、計上の後は計上した未払の額になり、二重にならない。中間申告（`annual.interim-return`）は額がないので印だけ。
- 給与を確定すると源泉所得税・住民税・社会保険料の納付が、申告と納付の期限には法人税等（均等割を含む）が額つきで線に入るので、それらを定期取引に重ねて登録しない（設定 › 定期取引の説明にも書く）。額のない期限（印だけ）の分は定期取引に登録してよい（印は線を動かさないので二重にならない）。

## 4. 線の描き方

- SVG（ライブラリは使わない。[14 §6](14-reports.md) の現預金の折れ線と同じ作り）。横は起点〜90 日後の日、縦は残高。残高は日の境で変わるので**階段状**（その日の残高を翌日まで水平に引き、変わる日に縦に動かす）に描く。線は primary、太さは拡大縮小しても変えない（`vector-effect: non-scaling-stroke`）。
- 起点に primary の点。縦の範囲は線の最小〜最大に 8% の余白。0 が範囲に入るとき（最小が 0 以下のとき）は 0 の線を引く。
- 0 円を割る日があるとき（残高 < 0 の日）: 0 の線を danger の破線にし、最初に割る日に danger の点。線の上に警告の行「2026/12/27 に残高が 0 円を割ります（-120,000 円）」を danger の色で出す。0 ちょうどは割ったとしない。
- 金額未定の納付は、その日の下端に muted の小さな目盛り（印）を付ける。印には題名を `<title>` で持たせる（ホバーで読める）。
- 横の目盛りは 起点・30 日後・60 日後・90 日後 の 4 つ（`M/D`）。縦の目盛りは最大と最小（と 0 の線を引くときは 0）を compact 表記（「150万」）。目盛りの文字は SVG の外（HTML）に置き、幅を縮めても字が潰れないようにする。
- 幅は親いっぱい（`width: 100%`、`viewBox` と `preserveAspectRatio="none"`）。高さは ホーム 140px（スマホ 120px）、報告 220px（スマホ 160px）。320px で横スクロールが出ない。
- 図の下に凡例は要らない（線は 1 本）。`role="img"` と `aria-label` に「90 日後 n 円、最低 n 円（日付）」を入れる。

## 5. ホームの下段 `/`

[14 §9](14-reports.md) のホームの最下段（損益とやることの下、案内文の上）に、幅いっぱいの 1 枚を足す。既存の段の中身は変えない。

- 見出し「資金繰り（90 日）」が `/reports/cashflow` へのリンク（他のカードと同じ `HomeCard`）。
- 上に数字を 2〜3 つ並べる（スマホは折り返す）: 「90 日後」n 円（日付）、「最低」n 円（日付）。0 円を割る日があれば、その前に §4 の警告の行。
- 線（§4）。
- 下に 1 行: 入っていないものが 1 件以上あれば「入っていない入力が n 件あります」（`/reports/cashflow#cashflow-notes` へのリンク）。定期取引が 0 件のときは代わりに「定期取引を登録すると、家賃や役員報酬の出金が線に入ります」（`/settings/recurring` へのリンク）。
- 帳簿も定期取引もない会社でも、平らな線と案内で欠けずに出る。

## 6. 報告 › 資金繰り `/reports/cashflow`

- タブの行に「資金繰り」を足す。順は [05 §2.5](05-ui-ux.md) に合わせ 試算表 / 月次推移 / セグメント損益 / 現預金 / **資金繰り** / 仕訳帳 / 総勘定元帳。既存のタブの中身と条件は変えない。
- 条件（期・期間・セグメント）は効かない（常に起点から 90 日・全社）。このタブだけ条件のフォームを出さず、PageHeader の meta は「2026/10/28 – 2027/01/26（90 日）」。タブのリンクは他のタブの条件を保ったまま（戻ったとき同じ条件で開く）。
- 上: 数字を並べる。「今日の現預金」（起点。ホームと同じ）・「90 日後」・「最低」（日付）。0 円を割る日があれば §4 の警告の行。
- 線（§4。報告の高さ）。
- 入っていないもの（`id="cashflow-notes"`）: §3.1 の注記を箇条で。すべて揃っていれば節ごと出さない。末尾に muted で「起点は登録済みの仕訳の残高です。取り込んでいない明細の分はずれます。土日祝の日付はずらしていません」。
- 予定の一覧: 期間内の予定を日付の順に（同じ日は 仕訳 → 定期取引 → 納付 → 請求・支払 の順、その中は名前の順）。列: 日付 ・ 内容（定期取引の名前 / 期限の題名 / 請求番号と取引先 / 仕訳の No. と摘要）・ 種類（取引 / 定期取引 / 納付 / 請求 / 支払）・ 口座（定期取引だけ）・ 入出金（円）・ 残高（円。その行までを足した残高）。金額未定の納付は入出金を「金額未定」、残高を「—」。現預金を動かさない定期取引は出さない。0 円を割る行は残高を danger の色。スマホは「日付・内容」と「入出金・残高」の 2 段。0 件なら「90 日のあいだに予定はありません」と §5 と同じ案内。
- 起点の内訳: 現預金の口座ごとの起点の残高（[14 §6](14-reports.md) の口座と同じ並び）と「口座に紐づかない現預金」。合計が今日の現預金。
- CSV: 予定の一覧（日付・内容・種類・口座・入出金・残高）。1 行目は「起点」の行（日付 = 起点、内容「今日の現預金」、残高 = 起点の値）。金額未定は入出金・残高を空欄。PDF は同じ表（縦向き）。ファイル名は `cashflow_<起点>-<90 日後>.csv`。書き出しは監査ログに `export.download`（kind `cashflow`、from = 起点、to = 90 日後）で残す（[14 §1](14-reports.md)）。

## 7. 設定 › 定期取引 `/settings/recurring`

- 設定の索引の「定期取引」を `/settings/recurring` に向け、要約は「有効 n 件」（0 件なら「0」）。
- PageHeader「定期取引」（戻り先 設定）。その下に 1 行「毎月・毎年決まって起きる入出金です。資金繰りの予測に使い、予定日が来たら 1 クリックで取引として登録できます（自動では登録しません）」（#54 の後。§10）。
- 一覧の中で直接編集（[10 §2](10-settings-and-setup.md) の型。取引先と同じ部品）: 主な列は 名前 ・ 入出金と金額 ・ 周期と日（毎年は月も）・ 口座 ・ 科目 ・ 終了日 ・ 状態。名前の隣の「詳細」で 開始日・取引先・セグメント・税区分・メモ を含むすべての項目を開いて編集する（PC の表を取引先の表と同じ幅に収めるため、開始日は一覧に出さない）。保存の状態（保存済み / 保存中 / エラー）を行に出す。

## 10. 定期取引からの登録（v2 #54）

予定日が来た定期取引を、1 クリックで取引として登録する（freee の取引テンプレート・定期の自動登録ルールに当たる。ただし自動では登録しない）。明細を取り込む口座の定期取引は明細の側（[15 §4](15-statements.md) の推定）で登録し、同じ定期取引・同じ月を二重に登録しない。

### 10.1 仕訳の型

定期取引 1 件は、収入 / 支出 / 振替 のどれか 1 つの入力一式（[11 §4.1〜§4.3](11-transactions.md)）として登録する。種類は列から導く（種類の列は持たない）。

| 種類 | 条件 | 仕訳（`buildSimpleEntry`） |
| --- | --- | --- |
| 振替 | `transferWalletId`（相手の口座）がある | 出金（金額 < 0）: 口座 → 相手の口座。入金（金額 > 0）: 相手の口座 → 口座。手数料なし。`kind = transfer` |
| 支出 | 相手の口座がなく、金額 < 0 | 支払元 = 口座、科目・税区分・取引先・セグメント |
| 収入 | 相手の口座がなく、金額 > 0 | 入金先 = 口座、科目・税区分・取引先・セグメント |

- `RecurringItem` に列を 1 つ足す: `transferWalletId`（相手の口座。振替だけ。`Wallet` への参照）。保存時に `accountId` を相手の口座の科目にそろえる（§3.2 の予測はそのまま効く）。相手の口座は 口座と違う有効な口座。
- 科目の制限は取引の画面と同じ（台帳の `ACCOUNT_NOT_ALLOWED`）: 収入は収益の科目、支出は 費用・現預金以外の資産・口座に紐づかない負債。口座に紐づく科目（現預金・カード・役員立替）と 仮払消費税・仮受消費税 は 収入・支出 の科目にできない。
- 設定 › 定期取引 の科目の select に optgroup「口座（振替）」を足し、口座を選ぶと振替になる（`transferWalletId` と、その口座の科目を保存）。
- #19 で作った行で、科目が口座に紐づく科目（例: 未払金 でカードの引落し）なのに相手の口座がないもの: その科目（と補助科目の区別なし）に紐づく有効な口座が 1 つなら、それを相手の口座とみなして登録する。2 つ以上なら登録できず、「相手の口座を選んでください（設定 › 定期取引）」。
- 摘要: 「家賃（2026 年 12 月分）」（名前 ＋ 発生月）。
- 税区分: 定期取引の税区分、なければ科目の既定の税区分。どちらもなければ登録できず「税区分を選んでください（設定 › 定期取引）」。振替は `na`（台帳の振替と同じ）。
- セグメント: 定期取引のセグメント → 科目の既定 → 口座の既定（11 §4 と同じ順）。収益・費用で空なら台帳の `SEGMENT_REQUIRED`。

### 10.2 予定日と「登録済み」

- 登録の対象（「予定日の発生」）: 有効な定期取引の発生日（§2.1）のうち `今日 − 92 日 < 発生日 ≤ 今日` で、開いている期間（会計期間の中で、`lockedThrough` より後）にあるもの。約 3 か月より前の発生は出さない（取引の画面で手で登録する）。
- 月のキー: 発生日の年月（`YYYY-MM`）。**同じ定期取引・同じ月は 1 回だけ登録できる**。
- 登録済み（導出する。登録の記録を別に持たない）: 次のどちらかがあれば、その月の発生は登録済み。
  - (a) `sourceKind = recurring`・`sourceId = <定期取引の id>:<YYYY-MM>` の仕訳で、取り消されていないもの（`status = posted`。反対仕訳でない）。
  - (b) 発生月の中の日付の仕訳で取り消されていないもののうち、口座の科目（口座の補助科目があればそれも）の行と定期取引の科目の行を両方持ち、口座の行の金額が定期取引の金額の絶対値と同じもの（明細から登録した・取引の画面で手で登録した・テンプレートから登録した）。
- 取引の画面で取り消すと (a)・(b) から外れ、やることに戻る（取り消した後に登録し直せる）。
- 口座に明細の取込があるか: 口座の `importer`（CSV 形式・Stripe・銀行 API）が設定されていれば「明細で登録する」側（§10.4）。この口座の発生は、この画面から直接は登録しない（後から取り込む明細と二重になるため）。

### 10.3 やること

- `HOME_TODO_SOURCES`（[14 §9](14-reports.md)）に `recurringDueTodo` を足す: 未登録の予定日の発生（§10.2。「登録する」「明細で登録する」の両方）の件数。行は「定期取引を登録する n 件」（バッジ n・`count`）で、`/settings/recurring/due` へ。0 件なら出さない。既存の行は変えない。
- 明細から登録すると (b) に当たるので、その発生はやることから消える。

### 10.4 定期取引の登録 `/settings/recurring/due`

- PageHeader「定期取引の登録」（戻り先 定期取引）。設定 › 定期取引 の一覧の上に「予定日の登録 n 件」のリンク（0 件なら出さない）。
- 節「登録する」（口座に明細の取込がない発生）: 行 = 日付 ・ 名前 ・ 口座 →（科目 か 相手の口座）・ 金額（`MoneyInput`。既定は定期取引の金額の絶対値で、編集できる）・「登録」（primary・sm）。登録で仕訳を作り、行は消えて「No. n を登録しました」のトースト（取引の詳細へのリンク）。拒否（締め済み・税区分なし・登録済み …）は行の下に赤字で出し、行は残す。日付は発生日のまま（変えない。変えたいときは取引の画面で登録する）。
- 節「明細で登録する」（口座に明細の取込がある発生）: 行 = 日付 ・ 名前 ・ 口座 ・ 金額 ・「明細を開く」（`/statements?wallet=<口座の id>`）。節の上に 1 行「この口座は明細を取り込むので、明細から登録します（二重に登録しないため）」。
- 並び: 日付の古い順、同じ日は名前の順。0 件なら「登録する定期取引はありません」。
- 320px: 行は「日付・名前」と「金額・登録」の 2 段で、登録が欠けない。

### 10.5 登録の操作 `postRecurringOccurrence`

`postRecurringOccurrence(db, { recurringItemId, month, amount }, { actor })`（`packages/db/src/recurring-post.ts`）。1 トランザクションで:

1. 定期取引の行を `FOR UPDATE` でロックする（同じ発生への同時の登録を直列にする）。
2. `month` の発生日を §2.1 で求める。その月に発生がない・無効・開始日前・終了日後・今日より後・§10.2 の範囲の外 は拒否（「家賃の 2027 年 1 月分はまだ予定日が来ていません」など、状態と戻り方を書く）。
3. 登録済み（§10.2 の (a)・(b)）なら拒否「家賃の 2026 年 12 月分は登録済みです（No. 12）」。
4. 口座に明細の取込があれば拒否「この口座は明細から登録します。明細を開いてください」。
5. §10.1 の型から `buildSimpleEntry` で仕訳を組み、`postJournalEntryInTransaction` で登録する（`sourceKind = recurring`・`sourceId = <id>:<YYYY-MM>`・日付 = 発生日）。金額は 1〜999,999,999,999 円の正の整数で、符号は型が決める。締め済み・期の外・税率の規則なしは台帳の拒否をそのまま、取引の画面と同じ文言で出す。
6. 監査ログ: 仕訳の登録（`journal_entry.post`）に加えて `recurring_item.post`（entity `recurring_item`、`after: { month, journalEntryId, amount }`）。

### 10.6 明細の推定に「定期取引」の段を足す

[15 §4](15-statements.md) の `suggest` の段の順を ルール一致 → 振替の候補 → **定期取引** → 過去の同じ摘要 → 取引先の既定 → 科目の既定 にする（先に決まった段を後の段が上書きしない決まりはそのまま）。

- 一致: 有効な定期取引のうち、口座 = 明細の口座、金額 = 明細の金額（符号つきで同じ）、明細の日付から ±7 日以内に発生日（§2.1）があり、その発生の月がまだ登録済みでない（§10.2）もの。複数なら発生日が近いもの、同じなら名前の順。
- 推定: 型が振替なら `mode = transfer`・相手口座 = 相手の口座。収入・支出なら `mode = register`・科目・税区分・取引先・セグメント（空は §4 の段 5 と同じく科目・口座の既定で埋める）。摘要は明細の摘要のまま。`source = recurring`、`recurringItemId` を持つ。チップは点線で、出どころに「定期取引 家賃」と出す。
- 取込時の自動登録（15 §11）はしない（`autoPost = false`）。
- 明細から登録した仕訳は `sourceKind = wallet_txn` のまま（明細の仕訳）。§10.2 の (b) に当たるので、その月の発生はやることから消え、同じ月の別の明細には定期取引の段が当たらない。
