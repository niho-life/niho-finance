# 05. 画面と体験

方針は「シンプル・スタイリッシュ・直感的」。会計の専門知識がなくても、毎月の経理が「明細を上から片付ける」だけで終わる画面にします。freee の情報量を参考にしつつ、1 社・数人に要らないもの（権限体系、承認フロー、多事業所、営業向けの機能）を削ります。NIHO アプリのデザインガイド（Morphoism、semantic token、骨格は漢語の名詞句、CTA は結果を表す動詞）を引き継ぎます。

モック: [`mock/v1.html`](mock/v1.html)（自己完結 HTML。ホーム・明細・取引・証憑・報告の主要画面）。

## 1. 情報設計

freee の「請求・入金 / 発注・経費・支払 / 取引入力 / 会計帳簿 / 分析・レポート / 決算申告 / 入力効率化 / マスタ・口座 / その他設定」を、日々の動線の順に畳みます。左のナビは、頻度で 日々・見る・業務・年次 の 4 群に分けます。設定は最下部に置きます（群と並びの正は [10 §1](10-settings-and-setup.md)）。

| ナビ | 役割 | 頻度 |
| --- | --- | --- |
| ホーム | 残高・今月の損益・やること・期限 | 毎日見る |
| 明細 | 取り込んだ明細を「登録・振替・無視」で片付ける | 週 1〜月 1 |
| 取引 | 仕訳の一覧・手入力・訂正 | 月数回 |
| 証憑 | 領収書・請求書の保存と紐づけ | 随時（スマホ） |
| 報告 | 試算表・月次推移・セグメント・現預金・資金繰り・帳簿 | 月 1 |
| 期限 | 申告・届出・納付の期限の一覧と、済ませた記録（[24](24-calendar.md)） | 月 1（期限の前後） |
| 請求（v2） | 見積・納品・請求と入金の消込 | 受託のとき |
| 立替精算（v3） | 社員・業務委託の立替の提出と支払（[23](23-users-and-expenses.md)） | 月 1 |
| 決算（v2） | 決算整理・固定資産・締め・決算書・申告用の書き出し | 年 1 |
| 設定 | 事業所・会計期間・科目・税区分・口座・取引先・セグメント・ルール・エクスポート・監査ログ | 初期と随時 |

スマホは下タブ 4 つ（ホーム / 明細 / 証憑 / 報告）に「その他」。スマホの仕事は「残高を見る」「明細を片付ける」「レシートを撮る」の 3 つに絞り、報告は閲覧だけにします。スマホはホーム画面に追加して使えます（[10 §1.1](10-settings-and-setup.md)）。

## 2. 画面ごとの設計

### 2.1 ホーム

一画面で「お金は今いくらあり、今月はどうか、何をすべきか」が分かる。

- 上段: 現預金の合計（大きな数字）と口座ごとのカード（残高・最終同期・未処理件数）。Stripe の残高は「入金待ち」として同じ列に並べる。
- 中段: 損益（売上・費用・利益）を 1 ブロックにし、「今月 | 今期」で切り替える。セグメント別の小さな横棒。クリックで報告へ。
- 右（スマホは現預金の直下）: やること を 1 つの一覧に。未処理の明細・受信箱の証憑・7 日以内の期限・7 日以内に支払う請求・発行する請求書・定期取引を登録するの件数。各行が該当画面への入口。0 件なら「今日やることはありません」。
- 下端に案内文を置かない（はじめての月は初月のガイドのカード）。
- 下段（v2）: 90 日の資金繰り線（残高の予測。定期取引と税金の予定を反映）。

### 2.2 明細

最も使う画面。1 行が 1 明細で、行の中で判断が完結する。

- 上: 口座のチップ（全部 / 口座ごと）、状態タブ（未処理 / 登録済み / 振替 / 無視）、検索。
- 行: 日付 ・ 摘要（取込そのまま。長いときは折返し） ・ 金額（右揃え、入金は通常色、出金は記号つき） ・ 推定（科目・税区分・取引先・セグメントのチップ。ルール一致は実線、推定は点線で区別） ・ 操作（登録 / 振替 / 無視）。
- チップをクリックすると、その場で候補から選び直せる（ポップオーバー）。摘要の右の「…」で証憑の紐づけ・メモ・分割（1 明細を複数行の仕訳に）。
- 複数選択で一括登録・一括無視。
- 「ルールにする」: 編集した結果を条件つきで保存。次回から自動登録か候補表示かを選ぶ。
- キーボード: ↑↓ で移動、Enter で登録、I で無視、T で振替、E で編集、R でルール、/ で検索。
- 振替: 相手口座の同額・近い日付の明細を候補に出し、1 クリックで 2 明細を結ぶ。候補がなければ相手口座を選ぶだけ。
- 登録直後は 5 秒の取消トースト。取消は内部では反対仕訳（帳簿の不変性を保つ）。

### 2.3 取引

- 一覧: 仕訳帳の見た目（日付・摘要・借方・貸方・金額・セグメント・証憑の有無）。期間・科目・取引先・セグメント・タグで絞り込み。
- 新規: 「収入」「支出」「振替」の 3 つの軽いフォーム（科目・金額・税区分・取引先・セグメント・日付・証憑）。複数行が要るときだけ「伝票」（借方・貸方の表）。
- 詳細: 行、証憑のサムネイル、生成元（どの明細・請求書から）、履歴（監査ログ）。「訂正」は理由を書いて反対仕訳を作り、複製した仕訳を編集して登録する流れ。「取消」は反対仕訳だけ。
- 締めた期間の仕訳は読み取り専用で、訂正は開いている最初の日付で作ることを画面に出す。

### 2.4 証憑

- 受信箱（未紐づけ）と「すべて」。PC はドロップゾーン、スマホはカメラ起動が主ボタン。
- 詳細: 左にプレビュー（画像 / PDF）、右に日付・金額・取引先・登録番号・種別。読み取り結果（v2）は提案として入り、確認して保存。
- 「この証憑から取引を登録」と「明細に紐づける」（同じ金額・近い日付の明細を候補に）。
- 検索: 日付の範囲・金額の範囲・取引先（電子帳簿保存法の検索要件）。
- 削除はなく「無効」。無効にした証憑も検索には出る（理由つき）。

### 2.5 報告

- タブ: 試算表（BS / PL） ・ 月次推移 ・ セグメント損益 ・ 集計（取引先別・タグ別・科目別 × 月別。v2） ・ 現預金 ・ 資金繰り（v2） ・ 消費税（v2） ・ 仕訳帳 ・ 総勘定元帳。
- 共通: 期間セレクタ（今月 / 今期 / 任意）、セグメントの切替、CSV と PDF の書き出し。
- 試算表の科目をクリック → 総勘定元帳（残高の推移つき） → 仕訳。数字は必ず元の仕訳まで辿れる。
- 月次推移は 12 列。科目ごとの折り畳み。前年同月（v2。第 2 期から）。
- 集計は収益か費用を取引先・タグ・科目・セグメントの軸で月別に並べ、上位 n 件と「その他」。行から総勘定元帳 → 仕訳へ辿れる（[14 §15](14-reports.md)）。
- 現預金は口座ごとの残高の折れ線と、明細の残高（`balanceAfter`）との差異の警告。

### 2.6 請求（v2）

- 一覧（状態: 下書き / 発行 / 送付 / 入金 / 無効）。期限超過を先頭に。
- 作成: 取引先・件名・明細行（品名・数量・単価・税率）。税率ごとの小計と消費税を自動で表示。適格請求書の記載事項が揃っているかの確認行。
- プレビューは PDF そのもの。「発行」で番号を確定し、PDF を証憑に保存、売掛金を計上。「送付」でメール。入金は明細から「この請求に充てる」で消込。

### 2.7 決算（v2）

- チェックリスト形式: 未処理 0 件 → 未紐づけ 0 件 → 残高の照合（銀行の残高証明・Stripe の残高） → 減価償却 → 前払・未払 → 消費税 → 法人税等 → 締め → 決算書 → 書き出し。各項目が該当画面への入口で、完了すると緑。
- 締めは確認ダイアログで「締める」。締めると期の仕訳はすべて読み取り専用。

### 2.8 設定

1 ページに節で並べる。事業所 / 会計期間 / 勘定科目 / 税区分 / 口座 / 取引先 / セグメント / タグ / ルール / 定期取引 / 証憑の規程 / 利用者（v3。[23 §4](23-users-and-expenses.md)） / 書き出しとバックアップ / 監査ログ。勘定科目と口座は表の中で直接編集（Google フォーム型の一覧編集）。

## 3. 見た目

- 白基調で、できるだけシンプルに（owner 決定 2026-10-28・[D14](../decisions/2026-10-28-ui-white-minimal.md)。Notion・STUDIO の画面が参考）。ページ背景も面も白。区切りは薄いグレーの線と余白で作り、入れ子のカードや塗りの面を作らない。影は浮いている操作要素（ポップオーバー・シート・ダイアログ）だけ。サイドバーだけ `#F7F7F5` のようなごく薄いグレーでよい。
- 色は semantic token（background / surface / text / muted / border / primary / danger / success）。文字は近い黒（`#1F1F1F` 程度）と 1 段階の muted グレー。primary は NIHO のブランド色 1 色で、CTA と焦点にだけ使う。金額のマイナスを赤で塗らない（記号と muted で表す。赤は警告だけ）。モックの v1 はクリーム地だが、実装は白にする。
- 数字は tabular figures、右揃え、3 桁区切り、単位は列見出し（「円」を各セルに書かない）。
- 文字: 本文 15px、表 14px、見出しは大きさより余白で階層を作る。重要な数字は 24〜32px。
- 行の高さは PC 40px、スマホは 2 段（摘要と金額 / 推定チップ）。
- 動き: 状態の変化（登録で行が薄くなって消える、取消で戻る）だけ。装飾のアニメーションは入れない。

### 3.3 読み込み中と体感速度

- 通常の画面遷移では、次の画面が用意できるまで現在の画面を残す。ナビの押した項目には待機中の印を出す（速い遷移では点滅させない）。画面全体の `loading.tsx` は一律に置かない。
- 骨格や `Suspense` は、その画面の実データで待機が長く、先に出す部分に利用者の価値があり、中身の表示時刻と LCP が悪化しないことを計測で確認した場合に限る。報告の表は数字を早く見せることを優先し、初期状態では見出しと表を一緒に描く。
- 初回表示の白い画面やコールドスタートは、TTFB と本番のインスタンス設定を測って対策する。画面全体の骨格でサーバー応答待ちを隠そうとしない。
- 最小インスタンスは 0 のまま（固定費の上限）。起動時に DB の接続や IAP の公開鍵を先回りして開く方法は、本番の計測で 1 回目を遅くしたので採らない（[決定](../decisions/2026-10-31-no-startup-warmup.md)）。起動直後の 3 件の要求は、IAP の検証と利用者の照会にかかった時間を `startup.request` のログに出す（#82）。
- Next.js の起動時の全ページの先読み（`experimental.preloadEntriesOnStart`）は切る。1 回目の要求には、その要求に要るモジュールだけを読む。ほかの画面は、そのインスタンスで初めて開いたときに読む（[決定](../decisions/2026-10-31-no-preload-entries.md)）。
- 一覧の「前へ」「次へ」は `Link` で次のページを先読みする。明細の登録・振替・無視は、確認後すぐ行を隠し、失敗時は同じ位置に戻して理由を行に出す。複数選択は対象行を先に隠し、サーバー処理は採番のため 1 件ずつ行う。
- 変更の判断は、同じデータと実行条件で初回表示の実測 LCP、クリックから中身までの時間、クリックから待機表示までの時間を比較する。Lighthouse のシミュレーション値だけで判断しない。

## 4. 文言

| 骨格（名詞句） | CTA（結果の動詞） |
| --- | --- |
| ホーム / 明細 / 取引 / 証憑 / 報告 / 請求 / 決算 / 設定 | 登録 / 振替 / 無視 / 保存 / 発行 / 送付 / 締める / 訂正 / 取消 / 書き出す |

- 内部の識別子（`wallet_txn`、`posted`、ルール ID）を見せない。
- エラーは状態と戻り方を書く（「この期間は締めています。開くには設定 › 会計期間から」）。
- 空状態は次の行動とセット（「明細がありません。口座を登録するか、CSV を取り込む」）。
- 金額の確認を伴う操作（締め・訂正・一括登録）は影響する件数と合計を確認ダイアログに出す。

## 5. アクセシビリティと確認

- キーボードだけで明細を片付けられる。フォーカスの見た目を消さない。
- 押せる範囲は 24px 以上。チップの間隔を空ける。
- 320px でホームと明細の主要操作が欠けない。
- 変更時の確認: 320 / 390 / 1280 幅、日本語長文、空データ、読み込み、エラー、キーボード、締めた期間の読み取り専用表示。
