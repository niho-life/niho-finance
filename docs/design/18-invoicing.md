# 18. 請求（v2 C の画面仕様）

Issue #16 の画面と台帳の仕様。受託開発（セグメント ③）の見積書・納品書・請求書を出し、請求書の発行で売掛金を計上し、入金を消し込む。設計の前提は [01 §5](01-domain-model.md)、[02 §4.4](02-accounting-rules.md)、[03 §2.3](03-compliance.md)、[05 §2.6](05-ui-ux.md)、[09 D1・D16](09-decisions.md)。台帳の操作は S3（[11 §1](11-transactions.md)）の API の上に作る。

## 1. 書類と状態

| 種別 | `docType` | 番号の接頭辞 | 台帳 |
| --- | --- | --- | --- |
| 見積書 | `quote` | `QT` | 計上しない |
| 納品書 | `delivery` | `DN` | 計上しない |
| 請求書 | `invoice` | `INV` | 発行で 売掛金 / 売上、入金で 普通預金 / 売掛金 |

状態は 下書き `draft` / 発行済み `issued` / 送付済み `sent` / 入金済み `paid` / 無効 `void`（画面では常にこの日本語で出し、内部の値は見せない）。

| 遷移 | 操作 | できる条件 | 起きること |
| --- | --- | --- | --- |
| （なし）→ 下書き | 作成・変換・複製 | — | 本文を保存する。番号はまだない |
| 下書き → 下書き | 編集 | 下書きだけ | 本文を書き換える（発行済みは書き換えない） |
| 下書き → 無効 | 破棄 | 下書きだけ | 論理削除。一覧の既定からは消える |
| 下書き → 発行済み | 発行 | 記載事項の確認に「不備」がない。発行日を含む会計期間がある。請求書は台帳が登録を受け付ける日付 | 番号を確定し、発行者と宛名を写し（`issuerSnapshot` / `recipientSnapshot`）、請求書は 売掛金 / 売上 の仕訳を登録する |
| 発行済み → 送付済み | 送付済みにする | 発行済み | 送付の日時と宛先を記録する。メール送付（§11）も同じ遷移 |
| 発行済み・送付済み → 入金済み | 入金の登録 | 請求書。残高 > 0 | 入金の仕訳を登録し、`payments` に 1 件足す。残高が 0 になったら入金済み |
| 入金済み → 発行済み・送付済み | 入金の取消 | 入金が 1 件以上 | 入金の仕訳を反対仕訳で取り消し、残高を戻す（送付の記録があれば送付済み、なければ発行済み） |
| 発行済み・送付済み → 無効 | 無効にする | 入金が残っていない（残っていれば先に入金を取り消す） | 請求書は 売掛金 / 売上 の仕訳を反対仕訳で取り消す。番号は残る |

派生する表示（列ではなく計算）:

- **残高** = 合計 − 取り消していない入金の充当額（入金額 ＋ 振込手数料）の和。請求書だけ。
- **期限超過** = 請求書で、発行済み・送付済みのまま 支払期限 < 今日。一覧の先頭に出す。
- **変換済み** = 見積書・納品書に、変換で作られた書類（`sourceInvoiceId` がこの書類）がある。

不変条件:

- 発行済み以後は本文（種別・番号・取引先・発行日・期限・件名・行・金額・写し・変換元・仕訳）を書き換えない。アプリの層で拒否し、DB のトリガーでも拒否する（`invoice` の UPDATE は `status` が `draft` のときだけ本文を変えられる。DELETE は常に拒否）。
- 番号は発行で 1 回だけ付け、再発行（PDF の再出力・再送付）でも無効でも変えない。欠番を作らない。
- 削除は論理削除（無効）だけ。台帳の取消は反対仕訳だけ（02 §1）。
- 作成・編集・破棄・発行・送付・入金・入金の取消・無効・設定の変更に監査ログ（`invoice.*`、設定は `company.update`）。

## 2. 番号

- 形は `<接頭辞>-<期>-<連番 4 桁>`。例 `INV-2026-0001`、`QT-2026-0003`。`<期>` は発行日を含む会計期間の開始日の西暦（第 1 期 2026-11-02〜2027-03-31 なら `2026`、第 2 期なら `2027`）。連番は種別と会計期間ごとに 1 から。9,999 を超えたら桁が増える（並び替えは数値で行う）。
- 発行の取引で種別ごとの advisory lock を取り、同じ接頭辞（`INV-2026-`）の最大の連番 ＋ 1 を付ける。無効にした書類の番号も数える（欠番にしない）。同じ西暦に始まる期が 2 つある（設立直後の短い期）ときは、連番がそのまま続く。`@@unique([docType, number])` が最後の守り。
- 下書きには番号がない。列は NOT NULL なので DB には `<接頭辞>-draft-<id>` を置き、画面には出さない（一覧・詳細とも「下書き」と出す）。発行で本物の番号に置き換える。
- 訂正は「無効にする → 複製 → 発行」で新しい番号になる。元の番号は無効の理由と、複製した下書きの備考の先頭（「INV-2026-0001 の再発行」）に残す。適格請求書の修正（修正インボイス）もこの形で、修正前の番号を書く。

## 3. 金額と消費税

### 3.1 行

| 項目 | 内容 |
| --- | --- |
| 日付 | 任意。取引年月日。空なら発行日を取引年月日とみなす |
| 品名 | 必須・200 字 |
| 数量 | 小数 2 桁まで、0 より大きい。内部は 100 倍の整数（`1.5` → `150n`）で持ち、浮動小数は使わない |
| 単位 | 任意・20 字（式・人日・時間 …） |
| 単価 | 円の整数。負の単価が値引き（「値引き」の行は 数量 1 × 単価 −5,005 のように書く） |
| 税区分 | 売上の税区分だけ: 課税売上 10% `sales_10` / 課税売上 8%（軽減）`sales_8r` / 非課税売上 / 不課税売上 / 輸出免税売上。既定は 10% |
| 金額 | 数量 × 単価。1 円未満は 0 に向けて切り捨て（`(数量×100 × 単価) ÷ 100`）。画面は自動計算で、サーバーも同じ式で計算し直す |

行は 1〜100。

### 3.2 税率ごとの集計（端数処理は 1 回）

単価の税は「税抜」（既定）か「税込」を書類ごとに選ぶ（`pricesIncludeTax`）。税率は `resolveTaxRule(税区分, 発行日)` で引く（S3 と同じ規則。規則がない課税の税区分は保存・発行を拒否し、行の税区分にエラーを出す）。

税区分ごとに行の金額を合計し、その合計に対して 1 回だけ端数処理する（03 §2.3。明細ごとの税額を足し上げない）。売上の税区分は税率と 1 対 1（`sales_10` = 10%、`sales_8r` = 8%）なので、税区分ごとの集計が税率ごとの集計と一致する。

| 表示 | 対価の額 | 消費税額 | 税込の額 |
| --- | --- | --- | --- |
| 税抜 | Σ 金額 | 対価 × 率 ÷ 100（切り捨て） | 対価 ＋ 消費税 |
| 税込 | Σ 金額（税込） | 対価 × 率 ÷ (100 ＋ 率)（切り捨て） | 対価 |

合計 = 税率ごとの税込の額の和。非課税・不課税・輸出免税は税率 0・消費税 0 の区分としてそれぞれ別に集計する。

値引きは税率ごとの対価から引いた後で税を計算する。税率ごとの税込の額が負になる書類、合計が 0 円以下の書類は発行できない（「値引きが 10% の対価の額を超えています」）。

例（テストのフィクスチャ。10% と 8% が混在し値引きあり。税抜表示）:

| 品名 | 数量 | 単価 | 税区分 | 金額 |
| --- | --- | --- | --- | --- |
| 設計・開発 一式 | 1 | 100,000 | 10% | 100,000 |
| 保守（2 か月） | 2 | 15,005 | 10% | 30,010 |
| 打合せの飲料 ※ | 3 | 345 | 8%（軽減） | 1,035 |
| 値引き | 1 | −5,005 | 10% | −5,005 |

10% 対象 125,005 円・消費税 12,500 円（行ごとに計算して足すと 12,501 円になる。足し上げない）、8% 対象 1,035 円・消費税 82 円、合計 138,622 円。

### 3.3 保存する形

JSON の金額は 10 進の文字列（bigint を浮動小数にしない）。

| 列 | 形 |
| --- | --- |
| `lines` | `[{ date: "2026-12-01" \| null, name, quantity: "1.5"（formatQuantity の形）, unit: string \| null, unitPrice: "100000", taxCategoryCode, amount: "150000" }]` |
| `subtotalByRate` | 税区分ごと: `{ "sales_10": { ratePercent: 10, reduced: false, taxable: true, lineCount: 3, subtotal: "125005", amountExclusive: "125005", amountInclusive: "137505" }, … }` |
| `taxByRate` | 税区分ごとの消費税額: `{ "sales_10": "12500", "sales_8r": "82" }` |
| `total` | 合計（bigint 列） |

表示のたびに計算し直さず、保存した値を出す（発行後に税率の規則が変わっても書類は変わらない）。下書きは保存のたびに計算し直し、発行の時点でもう一度計算して確定する。

## 4. 適格請求書と区分記載請求書

- 様式の判定は発行日で行う: `Company.invoiceRegistrationNumber` があり、`Company.invoiceRegisteredOn` ≤ 発行日 なら **適格請求書**、それ以外は **区分記載請求書**（D1 = C。登録は顧客が求めた時点）。判定の結果は `issuerSnapshot.qualified` に写し、発行後に設定が変わっても書類は変わらない。見積書・納品書も同じ記載事項で出す（登録番号は適格のときだけ）。
- **記載事項の確認行**（新規・編集・下書きの詳細に出す。発行の条件でもある）:

| 項目 | 適格 | 区分記載 | 判定 | 不備のときの文 |
| --- | --- | --- | --- | --- |
| 発行者の名称 | 必須 | 必須 | `Company.name` | 設定 › 事業所 で商号を入れてください |
| 登録番号 | 必須 | 出さない | 登録番号と登録日（発行日以前） | 適格のときだけ。区分記載のときは「登録番号なし。区分記載請求書として発行します」と情報として出す |
| 宛名 | 必須 | 必須 | 取引先が選ばれている | 取引先を選んでください |
| 取引年月日 | 必須 | 必須 | 行の日付、なければ発行日 | （常に満たす。内容を説明として出す） |
| 取引内容 | 必須 | 必須 | 全行に品名。軽減税率の行に ※ | n 行目の品名を入れてください |
| 税率ごとの対価の額と適用税率 | 必須 | 必須（税込の対価） | §3.2 の集計。合計 > 0、税率ごとの税込の額 ≥ 0 | 値引きが … の対価の額を超えています / 合計が 0 円です |
| 税率ごとの消費税額 | 必須 | 任意 | §3.2 の集計 | — |

「不備」が 1 つでもあれば発行ボタンを無効にし、サーバーも拒否する（同じ判定を `invoiceChecklist` で共有する）。

- 登録日が後から過去の日付になったとき（設立日に遡る登録）は、発行済みの書類を書き換えない。顧客が適格請求書を求めたら「無効にする → 複製 → 発行」で出し直す（§2）。
- 発行した写しは 7 年保存する: PDF を証憑 `invoice_out` として保存する（§11。S6 の保存 API と S7 の PDF 基盤が入ってから）。

## 5. 台帳の操作

発行日の売上計上（D16 と同じ考え方で、請求書の発行日を計上日にする。納品の月に合わせたいときは発行日をその日にする）。

### 5.1 発行（請求書）

| 借方 | 貸方 |
| --- | --- |
| 売掛金 1200（取引先）合計 | 売上の科目（既定 4040 売上高 受託開発。セグメント既定 受託）税区分ごとに 1 行 |
| | 税抜経理の期: 仮受消費税 2310（税額の合計）|

- 日付は発行日、`kind = normal`、`sourceKind = invoice`、`sourceId` = 書類の ID。摘要は「請求書 INV-2026-0001 架空デザイン合同会社」、売上の行の摘要は件名。
- 行の `amount` と `taxAmount` は書類の集計（§3.2）をそのまま使う: 税込経理の期は 税込の額 / 税額、税抜経理の期は 対価の額（税抜）/ 税額 で、仮受消費税の行に税額の合計。税額を仕訳側で計算し直さない（書類と帳簿の税額を一致させる）。非課税などの区分は `taxAmount` 0。
- 売上の科目は収益の科目から選べる（既定 4040）。セグメントは必須（台帳の `SEGMENT_REQUIRED`）。
- `postJournalEntryInTransaction` で登録する。締め済み・期の外・決算済みは台帳が拒否し、画面は発行日の項目にその文を出す（「2026/12/31 までは締めています。登録するには 設定 › 会計期間 で締めを戻してください」）。

### 5.2 入金の消込

| 借方 | 貸方 |
| --- | --- |
| 口座の科目 / 補助科目（入金額） | 売掛金 1200（取引先）入金額 ＋ 振込手数料 |
| 支払手数料 5400（振込手数料。税区分は科目の既定。税抜経理の期は 仮払消費税 1400 の行を足す） | |

- 日付は入金日、`sourceKind = invoice`、`sourceId` = 書類の ID。摘要は「入金 INV-2026-0001 架空デザイン合同会社」。手数料の行のセグメントは書類のセグメント（なければ 共通）。
- 充当額（入金額 ＋ 手数料）は残高以下。一部入金は残高を減らすだけで状態は変えない。残高が 0 になったら入金済み。
- 明細（`WalletTransaction`）から選んだときは、同じ取引で明細を `registered` にし `journalEntryId` を結ぶ（明細は `pending` のものだけ。行をロックして確かめる）。S5 の明細画面の「この請求に充てる」は S5 の merge 後に同じ関数を呼ぶ。
- 入金の取消は `voidJournalEntryWithOpenDate`（反対仕訳。締め済みなら開いている最初の日付）で、`payments` の該当行に取消の日時・理由・反対仕訳を書く。明細を使っていれば `pending` に戻す。

### 5.3 無効

- 請求書は 売掛金 / 売上 の仕訳を `voidJournalEntryWithOpenDate` で取り消す（理由は無効の理由）。見積書・納品書は状態を変えるだけ。
- 入金が残る請求書は無効にできない（帯で「先に入金を取り消してください」）。

## 7. 一覧 `/invoices`

- PageHeader: 題名「請求」、meta に「第 n 期」。右に 請求書 / 見積書 / 納品書（secondary・sm。`/invoices/new?type=…`）と 設定（ghost・sm。`/invoices/settings`）。
- 絞り込み（GET フォーム。URL が正）: 種別（請求書 = 既定 / 見積書 / 納品書 / すべて）、状態（未完了 = 既定: 下書き・発行済み・送付済み / 下書き / 発行済み（送付済みを含む）/ 入金済み / 無効 / すべて）、取引先、検索（番号・件名の部分一致）。パラメータは `type` `status` `partner` `q` `page`。select は変更で自動送信。
- 表（PC の列）: 番号 ・ 種別 ・ 取引先 ・ 件名 ・ 発行日 ・ 期限 ・ 金額 ・ 残高 ・ 状態。番号は下書きなら「下書き」。期限は請求書の支払期限、見積書の有効期限（納品書は「—」）。残高は請求書だけ。状態は 下書き / 発行済み / 送付済み / 入金済み / 無効 に、期限超過なら「期限超過（n 日）」を warn の文字で、変換済みなら「→ 請求書 INV-…」を添える。無効と入金済みの行は muted。
- 並び: 期限超過の請求書を先頭（期限の古い順）、続いて発行日の降順（下書きは作成日時の降順を発行日とみなす）。50 件ごとに「前へ / 次へ」。絞り込みに合う行は最大 1,000 件まで読み、並び替えと頁をアプリで行う（1 人会社の件数では十分。超えたら絞り込みを促す文を出す）。
- 行全体が詳細へのリンク。スマホは 2 段: 番号・取引先 / 件名・金額（＋状態）。
- 空のとき: 「請求書がありません。見積書か請求書から作ります」と 2 つのボタン。絞り込みで 0 件なら「条件に合う書類がありません」。

## 8. 新規 `/invoices/new` と編集 `/invoices/[id]/edit`

PC 前提のフォーム（320px は崩れなければよい）。native の input / select だけで作り、Tab と Enter で保存できる。

- 上に 請求書 / 見積書 / 納品書 の切替（新規だけ。編集では種別を変えない）。
- 頭の項目: 取引先（必須。顧客・両方・その他の取引先。横に「取引先を追加」→ `/settings/partners`）、件名（200 字）、発行日（既定 今日）、期限（請求書は「支払期限」で既定は発行日の翌月末、見積書は「有効期限」で既定は発行日の 30 日後、納品書は出さない）、単価の税（税抜 / 税込）、備考（1,000 字。書類に印字）。
- 請求書だけ「会計」の項目: 売上の科目（収益の科目。既定 4040 売上高 受託開発。取引先の既定の科目が収益ならそれ）、セグメント（既定は科目の既定、なければ取引先の既定、なければ 受託）。
- 行の表: 日付 ・ 品名 ・ 数量 ・ 単位 ・ 単価 ・ 税区分 ・ 金額（自動）・ ×。最初は 1 行。「行を追加」「値引きを追加」（品名「値引き」・単価を負で始める）。1024px 未満は 1 行を 2 段に畳む。
- 表の下に集計: 税率ごとに「10% 対象 125,005 円 / 消費税 12,500 円」、8% は「（軽減）」、非課税などはその名で。最後に 合計。`computeInvoiceTotals` を client でも呼ぶ（純粋関数）。
- 記載事項の確認行（§4）: 項目ごとに ✓ / 不備 / 情報 を並べる。不備があれば「保存」はできるが、詳細の「発行」が無効になる旨を出す。
- 送信は Server Action。新規は保存して詳細へ移り「下書きを保存しました」、編集は「保存しました」。失敗は項目の下に（行は `lines.<n>.<field>`）、項目に結べないものはフォームの上に。
- `from`（変換）: 変換元の 取引先・件名・行・備考・単価の税・科目・セグメント で埋め、保存時に `sourceInvoiceId` を付ける。変換元は 発行済み・送付済み（・入金済み）の 見積書 → 納品書 / 請求書、納品書 → 請求書 だけ（サーバーで検査）。発行日は今日、期限は既定の規則。
- `copy`（複製）: 同じ種別の下書きとして埋める。複製元が無効なら備考の先頭に「INV-… の再発行」を置く。`sourceInvoiceId` は付けない。
- 編集は下書きだけ。発行済み以後は `/invoices/[id]` へ戻し「発行済みのため編集できません。直すには無効にして複製します」の帯を出す。

## 9. 詳細 `/invoices/[id]`

### 9.1 頭と帯

- PageHeader: 題名「請求書 INV-2026-0001」（下書きは「請求書（下書き）」）、meta に「発行済み · 2026/12/01 発行 · 架空デザイン合同会社」。戻るは一覧へ（`?list=` で絞り込みを保つ）。
- 帯（該当するものだけ）: 下書き「発行すると番号が確定し、請求書は売掛金を計上します」/ 無効「無効（理由: …）。反対仕訳 No. x」/ 期限超過「支払期限 2026/12/31 を n 日過ぎています」/ 入金済み「2027/01/10 に入金済み」/ 変換元「見積書 QT-2026-0002 から作成」（リンク）/ 変換先「→ 請求書 INV-2026-0003」（リンク）/ 売掛金の仕訳「仕訳 No. n」（リンク）/ 様式「適格請求書」または「区分記載請求書（登録番号なし）」。

### 9.2 書類

書類の見た目で出す（PDF ができるまでの代わりでもあり、PDF と同じデータから描く）。

- 宛名: 取引先名 ＋「御中」、住所（あれば）。発行者: 商号・住所・代表者・登録番号（適格のとき）。発行済みは写し（snapshot）から、下書きは現在の設定から描く。
- 件名、発行日、支払期限 / 有効期限、番号。
- 行の表: 日付 ・ 品名 ・ 数量 ・ 単位 ・ 単価 ・ 税率 ・ 金額。軽減税率の行は品名の末尾に ※ を付け、表の下に「※ 軽減税率対象」。
- 集計: 適格は税率ごとに「10% 対象 125,005 円 / 消費税 12,500 円」（税込の単価なら対価は税込）。区分記載は「10% 対象（税込）137,505 円」と小さく「うち消費税相当額 12,500 円」。最後に合計（24px 太字）。
- 振込先（請求書。`issuerSnapshot.bankAccount`、下書きは請求の設定から）、備考。
- 320px では各欄を縦に積む。行の表は品名を全幅、数量×単価と金額を 2 段目に。

### 9.3 操作

状態ごとに出すボタン（PageHeader の右。CTA は結果の動詞）:

| 状態 | 操作 |
| --- | --- |
| 下書き | 編集（ButtonLink）/ 発行（primary → ConfirmDialog）/ 破棄（ghost・danger の文字色 → ConfirmDialog danger） |
| 発行済み・送付済み（見積書・納品書） | 納品書を作る / 請求書を作る（`/invoices/new?type=…&from=id`）/ 送付済みにする / 複製 / 無効にする |
| 発行済み・送付済み（請求書） | 入金を登録 / 送付済みにする / 複製 / 無効にする（入金が残っていれば出さず、帯で説明） |
| 入金済み | 複製 / 送付済みにする（送付の記録がなければ） |
| 無効 | 複製 |

- 発行の ConfirmDialog: 「見積書を発行します」。本文に 取引先・合計・予定の番号（`QT-2026-0003`。確定は保存時）・様式（適格 / 区分記載）、請求書なら「2026/12/01 付で 売掛金 138,622 円 / 売上 を計上します」。ボタン「発行」。成功で同じページに留まり「INV-2026-0003 を発行しました」のトースト。
- 送付済みにする: ConfirmDialog に 宛先（任意・200 字。取引先のメールがあれば初期値）。ボタン「送付済みにする」。メール送付（§11）が入ったら「メールで送る」を足す。
- 無効にする: ConfirmDialog danger。理由（必須）と「複製して新しい下書きを作る」のチェック。請求書なら「売掛金の仕訳 No. n を反対仕訳で取り消します（2026/12/01 付。締め済みなら開いている最初の日付）」。ボタン「無効にする」。チェックがあれば複製の新規画面へ移る。
- 破棄: ConfirmDialog danger「下書きを破棄します。一覧から消え、元に戻せません」。ボタン「破棄」。成功で一覧へ。

### 9.4 入金（請求書）

- 「入金」の節: 残高（24px）、入金の表（日付 ・ 口座 ・ 入金額 ・ 手数料 ・ 充当額 ・ 仕訳 No.（リンク）・ 操作「取消」）。取り消した入金は muted で「取消済み（理由）」。
- 「入金を登録」→ Sheet。上に 残高。明細の候補があれば「明細から」の一覧（未処理の入金の明細: 日付 ・ 口座 ・ 摘要 ・ 金額。残高に近い順。ラジオで 1 件）、下に「手入力」。項目: 入金日（候補の日付、なければ今日）、口座（銀行の口座。候補の口座）、入金額（候補の金額）、差額の扱い: 入金額 < 残高 のとき「差額 n 円を振込手数料にする」のチェック（差額が 1,100 円以下なら既定で on。それ以外は off で、残りは一部入金）。充当額と登録後の残高を文で出す。ボタン「登録」。
- 入金の取消: ConfirmDialog danger。理由（必須）。「仕訳 No. n を反対仕訳で取り消し、残高を n 円に戻します」。ボタン「取消」。

### 9.5 履歴

この書類の監査ログ（`entity = invoice`）を日時順に。列: 日時 ・ 操作（作成 / 変更 / 発行 / 送付 / 入金 / 入金の取消 / 無効 / 破棄）・ 実行者 ・ 理由。行を開くと before / after（S3 の `JsonPair`）。

## 13. 受け入れ条件

Issue #16 の条件に加えて:

- §3.2 の例の税額（10% 12,500 円・8% 82 円・合計 138,622 円）が行ごとの足し上げ（12,501 円）にならず、保存した `subtotalByRate` / `taxByRate` と詳細の表示、発行の仕訳の税額が一致する。
- 発行で 売掛金 / 売上（税抜経理なら 仮受消費税 も）の仕訳が `sourceKind = invoice` で登録され、無効で反対仕訳になり、取引の詳細から生成元が請求書と分かる。発行済みの書類は編集画面を開けず、DB の UPDATE も本文を変えられない。
- 明細から・手入力の両方で入金を登録でき、手数料の差額が 支払手数料 になり、一部入金は残高を減らすだけで、残高 0 で入金済みになる。入金の取消で残高と明細の状態が戻る。
- 登録番号と登録日のない事業所では区分記載請求書、発行日が登録日以後なら適格請求書の様式になり、写しに固定される。
- 320px で一覧と詳細（書類・入金）が横スクロールなしで使える。
- `npm run check`、`test:db`、`next build` が通る。
