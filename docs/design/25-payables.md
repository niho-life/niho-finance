# 25. 支払（受領した請求書の未払管理。v2 #48 の画面仕様）

Issue #48 の画面と台帳の仕様です。受け取った請求書（外注費・SaaS の請求書払いなど）を、支払期日と未払の残りで管理し、資金繰りの入力にします。freee の「支払管理レポート」「支払関連仕訳」に当たります。請求（[18](18-invoicing.md)）の売る側の裏返しで、画面は「請求 › 支払」に置きます。

前提にする設計:

- [13 証憑](13-documents.md): 受領した請求書は証憑（種別 `invoice_in`）。
- [15 明細](15-statements.md): 銀行の明細の登録と照合。
- [21 資金繰り](21-cashflow.md) §3.1: 予測の入力の「未払の請求」。
- [02 会計処理の規則](02-accounting-rules.md) §4.3: 銀行・カードの仕訳。

## 1. 方針と不変条件

- **支払は証憑に付く。** 受領した請求書の証憑（`Document`、種別 `invoice_in`）に、支払期日・支払元の予定・計上の仕訳を持たせます（§8 の列）。支払用の表は作りません。証憑がない請求書は、先に 証憑 でアップロード（または撮影）してから登録します。
- **計上**: 費用 / 未払金。
  - 未払金は 2100 の、補助科目なし・取引先つきの行です。
  - カードの未払金は、口座ごとの補助科目（[02 §2](02-accounting-rules.md)）で持っています。請求書の未払は補助科目を付けないので、カードの残高と混ざりません。
  - 2100 は口座に紐づく科目なので、取引の「支出」と明細の「登録」では選べません（`isReservedAccount`）。そのため、支払の画面が自分で仕訳を作ります。
- **未払の残りは導出する**（derive, don't sync。[00 §5](00-overview.md)）。残りの額も状態も保存しません。
  - 計上額は、計上の仕訳の 未払金（2100・補助科目なし）の貸方の合計です。
  - 支払済みは、証憑に紐づく（`DocumentLink`）登録済みの仕訳の、未払金（2100・補助科目なし）の借方の合計です。計上の仕訳、取消済みの仕訳、反対仕訳は数えません。
  - 未払の残り = 計上額 − 支払済み。
  - このため、明細の画面の「未処理に戻す」や取引の画面での取消で仕訳が消えれば、残りはその場で戻ります。支払の記録を別に持たないので、書き忘れや食い違いが起きません。
- 台帳の規則（[02 §1](02-accounting-rules.md)）はそのまま守ります。仕訳は書き換えず、取り消すときは反対仕訳です。
- 監査ログ（entity `payable`、`entityId` = 証憑の ID）:
  - `payable.register`（登録）
  - `payable.update`（期日・支払元の予定の変更）
  - `payable.pay`（支払の登録）
  - `payable.cancel_payment`（支払の取消）
  - `payable.cancel`（登録の取消）
  - 証憑そのものの変更と紐づけは、S6 の `document.*` が別に残します。

## 2. 状態（すべて導出）

| 状態 | 条件 | 一覧の既定（未払）に出るか |
| --- | --- | --- |
| 未払 | 計上の仕訳が登録済みで、残り = 計上額 | 出る |
| 一部支払 | 0 < 残り < 計上額 | 出る |
| 支払済み | 残り ≤ 0 | 出ない |
| 取消 | 計上の仕訳が取消済み（支払の画面の「登録の取消」、または取引の画面） | 出ない |

- 期限超過は、未払・一部支払で、支払期日 < 今日 のときです。
- 証憑が無効になった支払は、どの一覧にも出しません。差し替えは、新しい証憑が列を引き継ぎます（§8）。

## 3. 支払期日と支払条件

- 取引先に支払条件を持たせます（§8 の列）。いずれも整数で、31 は末日の意味です。
  - 締め日（`paymentClosingDay`）
  - 何か月後（`paymentDueMonths`。0〜3）
  - 支払日（`paymentDueDay`）
- 期日の既定 `defaultPayableDueDate(請求書の日付, 条件)`:
  1. 締め日: 請求書の日付以後で、日が締め日の最初の日を求めます。その月に締め日がなければ月末日にします。
  2. 期日: 締め日の月から「何か月後」の月の支払日です（その月に支払日がなければ月末日）。
  3. 例: 末締め翌月末払い（31・1・31）なら、10/15 の請求書は 11/30 です。20 日締め翌月 10 日払い（20・1・10）なら、10/25 の請求書は 12/10 です。
  4. 条件がない取引先は「請求書の日付の翌月末」にします（help で「取引先の支払条件を入れると既定になります」）。
- 登録のフォームで、取引先の支払条件をその場で直して「この取引先の支払条件として保存」できます（`partner.update` の監査ログ）。
- 支払条件は 3 つそろえるか、3 つとも空にします（DB の CHECK でも守る）。何か月後が 0（当月払い）のときは、支払日を締め日以後にします。
- 支払期日は請求書の日付以後にします。登録で期日を空にすると §3 の既定が入り、期日の変更で空にすると「期日なし」になります（資金繰りは起点の翌日に出金と見る。21 §3.1）。

## 4. 台帳の操作

### 4.1 登録（計上）`registerPayable`

| 借方 | 貸方 |
| --- | --- |
| 費用の科目（税込。税区分ごとに分ける） | 未払金 2100（補助科目なし・取引先） |
| 税抜経理の期: 仮払消費税 1400（控除できる分。経過措置は [11 §1](11-transactions.md) と同じ） | |

- **日付**: 請求書の日付（取引年月日）です。締め済み・期の外は台帳が拒否し、日付の項目に出します。
- **科目と税区分の既定**:
  - 科目は、取引先の既定の科目、なければ外注費 5100 です。費用・資産の科目から選べます。現預金・口座の科目・仮払仮受は選べません。
  - 税区分は、取引先の既定の税区分、なければ科目の既定の税区分です。
  - 取引先にも証憑（請求書）にも登録番号がないときは、課税仕入を「インボイスなし」の区分（`purchase_10_ni` / `purchase_8r_ni`）に寄せます。請求書に登録番号が書いてあれば適格請求書として扱います。この寄せは仕訳を組む関数の側でも必ずかけます。
- **セグメント**: 取引先の既定、なければ科目の既定、なければ共通です。
- **摘要**: 既定は「請求書 <取引先>」です。
- **仕訳の属性と記録**:
  - `kind = normal`、`sourceKind = manual`。この仕訳は取引の画面から取り消せます。取り消すと支払は「取消」になります（§2）。
  - 証憑と仕訳を `linkDocument` で結び、証憑の `payableEntryId`・`payableDueDate`・`payableWalletId` を入れます。
  - 証憑の種別が `invoice_in` でなければ `invoice_in` にし、空の検索の項目（取引年月日・金額・取引先）を埋めます（`updateDocument`）。
- **拒否する場合**: 1 つの証憑に登録は 1 回です。取消（計上の仕訳が取消済み）のあとは登録し直せます。無効の証憑は登録できません。

### 4.2 支払 `payPayable`

| 借方 | 貸方 |
| --- | --- |
| 未払金 2100（補助科目なし・取引先）充当額 | 口座の科目 / 補助科目（出金額） |
| 支払手数料 5400（出金額 − 充当額。税区分は科目の既定、税抜経理なら 仮払消費税） | |

- **入力**: 支払日、口座（有効な口座。銀行・現金・カード〔カードで払う〕）、出金額、明細（任意）。
- **金額の規則**:
  - 充当額 = min(出金額, 残り)。
  - 出金額 > 残り のときは、差額を振込手数料（こちら負担。支払手数料）にできます。差額が 1,100 円以下なら既定で入れ、上回るときは拒否します（「残り n 円を超えています」）。
  - 出金額 < 残り は一部支払で、残りがそのまま残ります。
- **明細から払ったとき**（`walletTransactionId`。未処理の出金で、口座が一致するもの）:
  - 仕訳は `sourceKind = wallet_txn`・`sourceId = 明細` です。明細の登録と同じ持ち方なので、明細の画面の「未処理に戻す」はこの仕訳を取り消して明細を未処理に戻し、残りは導出で戻ります。
  - 明細は S5 の `settleWalletTransactionWithEntry` で登録済みにします（`settledAt`・監査ログ `wallet_transaction.register`）。
  - 証憑を明細にも紐づけるので、明細の「証憑なし」が消えます。
- **明細なしのとき**: 現金払いや、明細をまだ取り込んでいない場合は `sourceKind = manual` です。
- 摘要は「支払 <取引先> <証憑の件名か元のファイル名>」です。証憑を支払の仕訳にも紐づけます。
- 支払日は請求書の日付以後にします。手数料の行は取引先を付けず、セグメントは計上した費用の行のもの（なければ共通）です。

### 4.3 支払の取消・登録の取消

- **支払の取消**（詳細の支払の行の「取消」。理由は必須）:
  - 明細から払ったものは、S5 の `reopenWalletTransaction` で明細ごと未処理に戻します（仕訳は反対仕訳）。
  - それ以外は `voidJournalEntryWithOpenDate` です（締め済みなら開いている最初の日付）。
- **登録の取消**（詳細の「登録を取り消す」。理由は必須）:
  - 支払が残っていれば拒否します（「先に支払を取り消してください」）。
  - 計上の仕訳を反対仕訳で取り消すと、状態が「取消」になります。
  - 証憑の列（`payableEntryId` ほか）は消さずに残します（履歴）。登録し直すと新しい仕訳で上書きします。
- 期日・支払元の予定の変更は台帳に関係しないので、いつでもできます（`payable.update`）。
- 無効の証憑: 支払の登録と期日の変更は拒否します。支払の取消と登録の取消はできますが、差し替え後の証憑が支払を引き継いでいれば拒否します（引き継いだ側で操作する）。

## 5. ルートと殻

| ルート | 画面 |
| --- | --- |
| `/payables` | 一覧（期日順 / 取引先別） |
| `/payables/new?document=<id>` | 登録（受領した請求書を選んで未払にする） |
| `/payables/[id]` | 詳細（`id` は証憑の ID） |
| `/payables/apply?statement=<id>` | 明細の出金を支払に充てる |

- **請求の切り替え**: 左ナビの「請求」は `/invoices` と `/payables` の両方で現在地にします（`NavItem` に `match` を足す）。`/invoices` と `/payables` の上に「請求書 / 支払」の切り替え（リンク）を置きます。
- **スマホ**: 「その他」に「支払」の行を足し、下タブの「その他」の対象に `/payables` を足します。
- **証憑の詳細（S6）**: 受領した請求書（または種別が未整理）で支払の登録がない証憑に「未払として登録」（`/payables/new?document=`）を出します。登録済みの証憑には「支払を開く」を出します。
- **明細の画面（S5）**: 未処理の出金の行の「…」に「この支払に充てる」（`/payables/apply?statement=`）を出します。

## 6. 一覧 `/payables`

- **PageHeader**: 題名「支払」、meta に「未払 n 件 · n 円」。右に「受領した請求書を登録」（primary・sm）で `/payables/new` を開きます。
- **上の 3 つの数字**（小さな面に横並び。スマホは縦。絞り込みに関係なく全体で数える）:
  - 未払の合計
  - 7 日以内に支払う（件数と金額。期限超過は含めない。ホームのやることの件数は 7 日以内と期限超過の合計）
  - 期限超過（件数と金額。0 でなければ warn の文字）
- **絞り込み**（GET。URL が正）:
  - 状態: 未払（既定。一部支払を含む）/ 支払済み / すべて。「すべて」でも無効の証憑は出しません。
  - 取引先、並び（期日順 = 既定 / 取引先別）、検索（取引先名・ファイル名・メモ）。
  - パラメータは `status` `partner` `view` `q` `page` です。
- **表**（PC の列）: 支払期日 ・ 取引先 ・ 内容（メモかファイル名）・ 請求日 ・ 金額 ・ 残り ・ 支払元の予定 ・ 状態。
  - 状態は「期限超過（n 日）」（warn）・「一部支払」・「支払済み」・「取消」です。
  - 並びは期限超過を先頭（期日の古い順）、続いて期日の昇順、期日のないものを最後にします。
  - 取引先別は、取引先ごとの見出しの行（残りの小計）の下に期日順です。
  - 50 件ごとに「前へ / 次へ」です。
- 行全体が詳細へのリンクです。スマホ（768px 未満）は 2 段で、期日・取引先 / 内容・残り（と状態）です。
- **空のとき**: 「未払の請求書はありません。受け取った請求書を 証憑 に保存してから登録します」と「受領した請求書を登録」を出します。絞り込みで 0 件のときは「条件に合う支払はありません」です。

## 7. 登録・詳細・充当

### 7.1 登録 `/payables/new`

- **証憑**（必須）:
  - `?document=` で来たらその証憑です。なければ候補から選びます。候補は、受信箱か受領した請求書で、無効でなく、支払の登録がないもの（新しい順・20 件）です。
  - 選んだ証憑は、ファイル名・取引年月日・金額・取引先と、「証憑を開く」（`/api/documents/[id]/file`）で出します。
- **項目**（証憑の検索の項目と取引先の既定で埋める。読み取り #18 が入れば、その結果を受け入れた検索の項目から 1 回で埋まる）:
  - 取引先（必須）と請求書の日付（必須）
  - 支払期日（§3 の既定。日付の help に支払条件を出す）
  - 金額（税込・必須）、科目、税区分、セグメント、摘要
  - 支払元の予定（口座。任意）
  - 支払条件（その取引先の締め日・何か月後・支払日と「この取引先の支払条件として保存」）
- 「うち消費税 n 円」と、税抜経理なら仮払消費税の行を金額の下に出します（11 §4 と同じ計算）。
- 「登録」（primary）で詳細へ移り、トーストは「<取引先> の請求書を未払として登録しました（No. n）」です。失敗は項目の下に、項目に結べないものはフォームの上に出します。
- 作成は PC 前提でよく、320px で崩れなければ足ります。

### 7.2 詳細 `/payables/[id]`

- **PageHeader**: 題名「<取引先> の請求書」、meta に「未払 · 期日 2026/11/30 · 残り 110,000 円」。戻るは一覧へ。
- **帯**（該当するものだけ）:
  - 期限超過（n 日、warn）
  - 一部支払（支払済み n 円 / 残り n 円）
  - 支払済み
  - 取消（計上の仕訳が取消済み。「登録し直す」）
  - 証憑が無効
- **事実の表**: 取引先 ・ 請求書の日付 ・ 支払期日 ・ 金額（計上額）・ 残り ・ 支払元の予定 ・ 計上の仕訳（No. n へのリンク）・ 証憑（ファイル名と「証憑を開く」）。
- **操作**:
  - 「支払を登録」（primary・Sheet）: 上に残りを出し、その下に明細の候補を出します。候補は、未処理の出金で、日付が請求書の日付以後、金額の絶対値が残り＋1,100 以下のもの。残りに近い順・20 件で、ラジオで選びます。「手入力」も選べます。差額の扱い（手数料にする / 一部支払）と、支払後の残りを文で出します。
  - 「期日・支払元を変える」（Sheet）
  - 「登録を取り消す」（ghost・danger の文字色 → ConfirmDialog。理由必須。支払が残っていれば出さず、帯で説明）
- **支払の表**: 日付 ・ 口座 ・ 出金額 ・ 充当額 ・ 手数料 ・ 仕訳 No.（リンク）・ 「取消」。取消済みの支払は出しません（導出なので消える）。
- **履歴**: 監査ログ（`entity = payable`）と、証憑に紐づく仕訳の取消（明細の画面の「未処理に戻す」・取引の画面の取消）の日時順です。どこから取り消したかを出します（「支払の取消（明細を未処理に戻す）」など）。差し替え前の証憑の履歴もさかのぼって出します。
- 320px で横スクロールが出ないこと。

### 7.3 明細から充当 `/payables/apply?statement=<id>`

[18 §9.4](18-invoicing.md) の「この請求に充てる」と同じ形です。

- 上にその明細を出し、下に充てられる支払を出します。対象は、未払・一部支払で、請求書の日付が出金日以前、残りが |出金額| − 1,100 以上のものです。残りが |出金額| に近い順・20 件で、同じ取引先を先にします。
- 行の「この支払に充てる」→ ConfirmDialog（出金額・残り・差額の扱い・充当後の残り）→「登録」で `payPayable`（明細つき）し、明細の画面へ戻ります。
- 処理済み・入金・無効の口座の明細は理由を出します。候補がなければ「充てられる支払がありません」です。

## 8. データと層

### 8.1 schema（列の追加だけ）

- **`Document`**:
  - `payableEntryId String?`（`JournalEntry`、計上の仕訳）
  - `payableDueDate Date?`（支払期日）
  - `payableWalletId String?`（`Wallet`、支払元の予定）
  - `@@index([payableDueDate])`
  - 差し替え（S6 `replaceDocument`）で新しい証憑に引き継ぎます（追記）。DB のガード（`storage_key` などの不変）には触れません。
  - 証憑が仕訳を参照するので、バックアップの表の順（`BACKUP_TABLES`）で `document` と `import_batch` を仕訳の後ろへ移します。
- **`Partner`**: `paymentClosingDay Int?`・`paymentDueMonths Int?`・`paymentDueDay Int?`（CHECK: 3 つそろうか 3 つとも空、1〜31・0〜3・1〜31）。

### 8.2 `packages/ledger/src/payables.ts`（新規・純粋）

- `defaultPayableDueDate(invoiceDate, terms | null)`（§3）、`describePaymentTerms(terms)`（「末締め翌月末払い」「20 日締め翌月 10 日払い」）。
