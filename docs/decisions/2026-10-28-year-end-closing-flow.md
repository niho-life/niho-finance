# 決算整理中の期の扱い（期末の月の締めと、決算整理仕訳の取消）

## 状況

台帳（S1 の `validateEntry`）は、決算中（`closing`）の期に決算整理（`adjusting`）と決算振替（`closing`）の仕訳だけを受け付け、月次の締め（`lockedThrough`）以前の日付をすべて拒否する。決算整理仕訳は期末日付で登録する。このままだと次の 2 つが起きる。

- 3 月分を月次で締めてから（07 §5 の手順 1）決算整理を始めると、期末日が締め済みなので決算整理仕訳を登録できない。
- 決算中に決算整理仕訳を誤って登録しても、取消の反対仕訳（`reversal`）が拒否されるので取り消せない。締めを戻すときの決算振替の取消も同じ。

## 決定

- 決算整理を始める（open → closing）とき、締め日が期末日まで進んでいたら、期末日より前の最後の月末に戻す。決算中は通常の仕訳を受け付けないので、期末の月の取引は変わらない。決算中と締め済みの期は月次の締めを変えられない。
- 決算中の決算整理仕訳の取消と、締めを戻すときの決算振替の取消は、1 つのトランザクションの中で期を進行中として扱い、S3 の `voidJournalEntryInTransaction` で反対仕訳を登録してから決算中に戻す。期の行はロックしたままなので他のトランザクションからは見えず、監査ログは通常の取消と同じ 2 行に、遷移の 1 行が加わる。
- 本来の形（台帳の規則に「決算中の期に、決算整理・決算振替の反対仕訳を許す」を入れる）は #4 に相談し、入ったら置き換える。

## 理由

- 月次の締めは「期の途中の月を変えない」ための仕組みで、期末の月を変えない役割は決算中の状態が兼ねる。締め日を戻しても通常の仕訳は入らない。
- 台帳の不変条件（貸借一致・反対仕訳による取消・監査ログ）はどれも守られる。S3 の `entries.ts`・`journal.ts` は #14 の契約で触らないので、遷移の側で扱う。

## 影響

- `docs/design/16-year-end.md` §1。`packages/db/src/closing.ts` の遷移と、月次の締めの拒否。
- 取引の詳細画面（S3）は決算中の仕訳の取消を止めたまま。決算中の決算整理仕訳は決算の画面から取り消す。
