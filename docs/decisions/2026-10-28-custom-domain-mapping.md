# 画面に会社のドメインのサブドメインを付ける（S8）

- 状況: [06 §3.3](../design/06-architecture.md) は v1 を `run.app` の URL で始め、独自ドメインは証明書の運用を理由に v2 以降としていた。S8 の確認でオーナーが会社のドメインのサブドメインを希望した（`run.app` でもよい。費用や制約が出るなら `run.app`）。
- 決定（owner 2026-10-28）: 画面サービス `niho-finance` に Cloud Run のドメインマッピングでサブドメインを付ける。DNS は Cloudflare に CNAME（`ghs.googlehosted.com`、プロキシなしの「DNS のみ」）。ジョブ用サービスは `run.app` のまま。正確なホスト名はリポに書かず、`scripts/deploy.env` の `APP_URL` に置く。
- 理由: ドメインマッピングは追加費用がなく、証明書は Google が発行・更新するので 06 §3.3 の懸念（失効の監視）は小さい。ロードバランサで付ける方法は月 2,500 円以上で、予算（月 300 円以内）を超える。同じプロジェクトの NIHO アプリも同じ方式を使っている。IAP はサービスに掛かるので、独自ドメインでも `run.app` でも同じ許可リストで通る。
- 制約: ドメインマッピングはプレビュー機能で、Google は本番向けに推奨していない。止まったときは `run.app` の URL で使い続けられる（両方をブックマークする）。
- 影響: 06 §3.3、`docs/ops/deploy.md` §10、メールに載る画面の URL（`APP_URL`）。
