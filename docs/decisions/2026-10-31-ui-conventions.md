# UI の作法の表を 05 §3.1 に置き、以後の画面はこれに従う（#69）

- 状況: 画面ごとに文字の色・空状態・ボタンの語・負数の表記・フォームの送信中・ダイアログの焦点がばらついていた。全画面を 1280px / 320px で棚卸しすると、読ませる文字の `muted-2`（白地で約 2.8:1）が約 90 か所、負数の ASCII `-`、次の行動のない空状態、名詞だけのボタン、開閉で焦点の行き先が決まらないダイアログが見つかった（[05 §3.2](../design/05-ui-ux.md)）。
- 決定: [05 §3.1](../design/05-ui-ux.md) の作法の表を正とし、部品で決まるものは部品で守る。主なもの:
  - 読ませる文字は `text` か `muted`（約 5.3:1）。`muted-2` は無効の状態と装飾（「›」・開閉のアイコン・グラフの線）だけ。
  - 金額の負数は画面の表示だけ「−」（U+2212）にする。CSV・書き出し・PDF・入力の値・aria は `-` のまま、決算書の △ もそのまま。
  - 空状態は「題＋説明＋次の行動」、ボタンは結果を表す動詞。
  - フォームは送信中に送信ボタンを無効にして「…中」と出す。
  - Sheet と ConfirmDialog は共通のフック `useModalDialog` で、開いたら中の最初の入力へ、閉じたら開いたボタンへ焦点を戻す。ConfirmDialog の初期の焦点は「キャンセル」。
- 理由: 本文のコントラストを WCAG AA（4.5:1）以上にし、帳簿の数字と補足を読み違えにくくする。負数の記号を表示だけにするのは、書き出しや入力の値を他のソフトが読める ASCII のまま保ち、帳簿のデータに手を入れないため。ConfirmDialog で確定を初期の焦点にしないのは、Enter の打ち間違いで取消・無効などを確定しないため。
- 影響: 05 §3.1・§3.2、11・12・16 の文言。給与・書き出し・固定資産・証憑の詳細・請求の一覧・その他・明細の部品は #69 の 2 本目で同じ規則に合わせる。帳簿の値と書き出しの形式は変わらない。
