# 全画面の骨格を標準にせず、実データの表示を優先する（#72）

- 状況: 全セグメントに `loading.tsx` を置いた試作では、Mac Studio の同じフィクスチャによる実測で試算表の LCP が 125 ms から 492 ms へ悪化した。アプリ内遷移でも骨格は約 7 ms で出たが、中身は通常の 44〜298 ms から約 311 ms（試算表は 643 ms）に遅れた。React の Suspense は短時間に準備できた内容の表示も最大 300 ms 単位にまとめる。
- 決定: 主要画面へ `loading.tsx` を一律に追加しない。現在の画面を保持し、クリックしたナビ項目の待機状態を控えめに示す。報告の表も、実測で利点が確認されるまで別の Suspense 境界へ移さない。遅い画面はデータ取得・計算・本番 TTFB を先に調べ、境界は画面ごとに実測で決める。
- 理由: 帳簿の数字が早く読めることを優先する。画面形の骨格を全画面に置いても、サーバーが速い状態では表示を約 300 ms 遅らせる。コールドスタートによる応答待ちはサーバー側の課題であり、骨格の配置だけでは短くならない。
- 再検討条件: 本番相当のデータ量・ネットワークで、対象画面の有用な部分を先に描け、実測 LCP と中身の表示時刻が改善する場合は、その画面に限って骨格や Suspense を加える。試算表は改善前 LCP 125 ms より短いことも確認する。
- 計測: [Issue #72 の実測と A/B/C の比較](https://github.com/niho-life/niho-finance/issues/72#issuecomment-6488839655)。
