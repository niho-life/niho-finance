# 財務諸表 CSV の科目コード表は版ごとに取り込み、期の提出日で版を選ぶ

- 状況: 財務諸表 CSV（HOT010 Ver.3.0）の勘定科目コード表は国税庁が改訂することがある（現行は 2019 年版・令和 2 年 4 月 1 日以後提出分）。`Account` に e-Tax のコードを持たせるだけだと、コード表が変わったときに提出済みの期の CSV も変わってしまう（Issue #15「科目コード表の版を変えても過去の期の出力が変わらない」）。
- 決定: コード表は `packages/reports/data/etax/<form>-<version>/<edition>/` に版ごとの JSON（コード表・標準テンプレートの既定の対応・出どころと SHA-256）として取り込み、既存の版は書き換えない。期ごとに「`effectiveFrom` が提出日（期末の 2 か月後とみなす）以前の版のうち最新」を使う。科目の上書き（`Account.eTaxCode`）はその版のコード表にあるときだけ効き、なければ版の既定に戻して確認に出す。階層番号と行区分はコード表から決め、`Account.eTaxHierarchy`・`eTaxRowKind` は使わない。
- 理由: 版の追加だけで翌期以降に新しい表が効き、過去の期の出力は版のファイルが変わらない限り同じになる（テストで固定）。科目ごとに版の数だけ列を持つより単純。
- 影響: 年 1 回、決算の前にコード表と記載要領の更新を確かめる（`docs/ops/filing.md`）。新しい版を足すときは `tools/convert_code_tables.py` で JSON を作り、`default-mapping.json` を見直す。[17 §6](../design/17-financial-statements.md)
